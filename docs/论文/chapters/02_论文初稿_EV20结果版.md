# PeakAware：面向完整训练物理峰值预算的选择性激活重计算

状态：`draft`。本文档是基于冻结证据 `EV-20` 的论文初稿结果版。正文中的实验数字来自
`artifacts/paper_full_matrix_combined_paired_5budget_5pass_r1/`，结论只限定在该 artifact 覆盖的
四个 workload、两个编译后端、diagnostic hints 开/关、五个相对预算比例和当前硬件软件环境内。

## 摘要

Activation checkpointing、Selective Activation Checkpointing 和 AOTAutograd min-cut 等技术通过减少
跨 forward/backward 边界保存的 activation，在训练中提供显存与重计算开销之间的权衡。然而，saved
activation 目标并不直接等价于完整训练 step 的物理峰值：逻辑 tensor 可能共享底层 storage，backward
重计算会产生瞬时 live set，参数、梯度、optimizer state 和 compiler workspace 也可能成为新的峰值来源。

本文提出 PeakAware，一个面向静态 shape、单设备 PyTorch 编译训练的选择性重计算系统。PeakAware 在一次
AOTAutograd joint graph 捕获后构建 storage-aware IR，使用 D0--D5 分层模型解释 saved-memory 预期收益与
runtime physical peak 的差距，并基于诊断结果修复 SAVE 集合。系统随后只对少量多样化 Pareto Top-K 候选
执行 lowering、正确性验证和完整训练 step 实测，最终选择满足物理预算的 executable。

我们在 BERT-like-2L-64H、GPT2-like-2L-64H、ResNet-50 和 ViT-B/16 上评估 PeakAware，覆盖 AOT eager 与
Inductor 两个后端、diagnostic hints 开/关、50/65/80/95/100% all-save measured peak 五个预算比例和五次
matrix pass。冻结矩阵共 400 条记录，其中 200 条成功、200 条因预注册的不可行预算失败，失败样本保留在
分母中；所有成功记录均未发生预算违约。实验显示，raw 峰值估计的平均绝对百分比误差为 62.33%，使用
all-save residual/phase 校准后降至 6.54%，84.25% 的校准估计落在 10% 误差内。诊断结果表明收益缺口主要
来自 rematerialization wave、workspace growth、fixed frontier 和 cost-model misrank；hints 消融结果为
mixed，说明当前诊断更适合作为解释和候选修复证据，而不能被包装为稳定吞吐收益来源。本文的主要结论是：
在完整 step 物理峰值预算下，activation saved-memory 优化必须与 storage/phase/fixed/compiler-aware 诊断、
可执行计划下发和 runtime measurement 闭环结合，才能形成可核验的预算选择。

## 1 引言

GPU 显存限制了训练时可使用的 batch size、sequence length 和模型规模。对于许多模型，前向阶段产生的
activation 需要保存到反向阶段使用；如果全部保存，训练速度较快但显存压力较大。Activation checkpointing
通过丢弃部分 activation 并在 backward 中重计算它们降低保存量，Selective Activation Checkpointing 和
AOTAutograd min-cut 进一步把保存与重计算决策放入编译或策略接口中，使 memory--compute tradeoff 可以被更
系统地搜索。

这些方法优化的代理目标通常是 saved-for-backward activation 或某个 forward/backward cut 上的内存预算。
该目标很有价值，但并不等价于用户真正面对的约束。用户最终关心的是完整训练 step 中 CUDA allocated
physical peak 是否超过设备或任务预算。完整 step 的峰值可能出现在 forward、backward 或 optimizer phase；
它还受到 storage alias、recompute transient、gradient/optimizer fixed frontier 和 compiler materialization
影响。因此，减少 saved activation 不能保证 overall peak 同比例下降，甚至不能保证新的峰值仍位于原来的
forward/backward 边界。

本文研究如下问题：给定静态 shape、单设备训练任务、候选 SAVE 集合和物理峰值预算 `B`，如何选择一个数值
正确的 executable，使完整 step 的 measured allocated peak 不超过 `B`，并在预算内尽量优化稳态 step time 或
throughput？这个问题与“如何最小化 saved activation bytes”不同。后者是重要的规划信号，前者才是本文的验收
目标。

PeakAware 的核心思想是把代理目标与物理预算之间的差距显式化。系统先在 AOTAutograd joint graph 上抽取
storage-aware IR，然后用 D0--D5 层级模型从 logical saved values、storage normalization、recompute liveness、
fixed frontier、compiler correction 到 runtime measurement 逐层解释峰值变化。诊断结果既用于输出根因，也
用于修复候选 SAVE 集合。由于静态 cost ranking 仍可能不可靠，PeakAware 最终通过 Pareto Top-K measurement
闭环选择满足预算的计划。

本文贡献如下。

1. 提出 saved-memory 目标与 complete-step physical peak 目标之间的差距分解，将 expected saved gain、
   normalized saved gain、after-FW retained gain 和 overall peak gain 区分为可测量量。
2. 设计 D0--D5 storage/phase/fixed/compiler-aware 诊断模型，用于解释 alias、重计算波、固定前沿和编译器
   runtime offset 对峰值预算的影响。
3. 实现 PeakAware 的可执行闭环：候选 SAVE 集合被 lower 为 AOT FW/BW executable，并经过正确性验证和完整
   step measurement，而不是只作为静态标签报告。
4. 基于冻结 EV-20 矩阵给出四 workload、两个 backend、五预算比例下的预算满足、预测误差、phase peak、
   baseline 对照、Top-K 成本和 hints 消融结果。

本文不声称首次提出 activation rematerialization，也不声称全面优于 PyTorch min-cut、SAC 或所有 AC 方法。
实验中的 BERT 和 GPT2 workload 是小规格 BERT-like-2L-64H 与 GPT2-like-2L-64H，不外推到标准 BERT-Base 或
GPT-2；结论也不外推到 dynamic shape、多设备、FSDP/ZeRO、offload 或未测硬件。

## 2 背景与相关工作

### 2.1 Activation saving 与 rematerialization

神经网络训练通常包含 forward、backward 和 optimizer 三个阶段。Forward 产生的中间 activation 中，一部分
会被 autograd 保存，以便 backward 计算梯度。Activation checkpointing 的基本做法是不保存某些中间值，而在
backward 需要它们时重新执行相应 forward 片段。这样可以减少跨 forward/backward 边界的保存量，但需要增加
计算。

Rematerialization 已经被 Checkmate、Dynamic Tensor Rematerialization、Rockmate 等工作从静态优化、在线驱逐
和层次化求解等方向充分研究。PeakAware 不试图替代这些通用 rematerialization 问题形式化；本文关注的是
compiled PyTorch 训练中，已有 saved-memory 代理目标与 complete-step allocated physical peak 之间的语义差距，
以及如何把该差距接入可执行的 AOT plan selection。

### 2.2 AOTAutograd 与 min-cut 目标

PyTorch AOTAutograd 可以捕获 joint forward/backward graph，并由 partitioner 决定哪些值跨边界保存、哪些值
在 backward 中重算。Min-cut partitioner 的目标是在特定代价模型和允许重算集合下优化 forward/backward
partition。这个目标是合理且有用的，但它并不直接约束 graph 内部、optimizer phase 或 compiler workspace 的
完整 step 峰值。

因此，本文对 min-cut 的态度不是“否定”，而是“限定”。AOT min-cut 优化的是一个边界目标；PeakAware 额外关注
完整 step physical peak 是否满足预算，并在必要时通过 measurement 纠正静态估计。

### 2.3 物理峰值口径

本文默认“峰值”指 CUDA allocated physical peak，即完整 step 中
`max(FW peak, BW peak, optimizer peak)`。Reserved memory 只用于 allocator 保留池和碎片分析，不作为主优化
目标。Optimizer 位于 AOT joint graph 外，但包含在完整 step measurement 内；因此，即使一个 SAVE 集合降低了
after-FW retained activation，也可能因为 optimizer frontier 成为主峰而无法带来 overall peak 收益。

### 2.4 与现有工作的关系

Checkmate 等工作强调 memory--time tradeoff 的全局规划；DTR 强调在线 rematerialization；Rockmate 利用模型
结构和求解器组合降低搜索成本；PyTorch AC/SAC/min-cut 提供实用的策略接口和编译基础设施。PeakAware 的差异
在于，它把优化目标显式放在完整训练物理峰值预算上，并把 storage-aware diagnosis、SAVE repair、plan identity、
lowered executable、correctness validation 和 runtime measurement 连接成闭环。

## 3 问题定义与目标错位

设训练任务由模型 `M`、静态输入 shape、loss、optimizer、dtype、compiler backend 和设备环境确定。AOTAutograd
joint graph 给出可被保存或重算的值集合。一个候选计划 `p` 对应一个 SAVE 集合 `S_p`，并通过 lowering 得到
forward/backward executable。给定物理预算 `B`，系统需要选择满足以下条件的计划：

```text
correct(p) = true
measured_allocated_peak(p) <= B
```

在满足硬约束后，系统优化 steady-state step time 或 samples/s。若固定 frontier 已超过预算，或所有可执行候选
都不能满足预算，系统应报告 infeasible，而不是静默删除该点。

为了描述 saved-memory 与 physical peak 的错位，本文区分四类量。

- `strategy_expected_saved_gain`：策略或模型预期可以减少的 logical saved bytes。
- `normalized_saved_gain`：考虑 storage alias 后真实可能释放的 storage bytes。
- `after_fw_gain`：forward 结束、backward 开始前 retained activation 的下降。
- `overall_peak_gain`：完整 step allocated physical peak 的下降。

它们之间的差距由三类 gap 描述：

```text
strategy_estimation_gap = strategy_expected_saved_gain - normalized_saved_gain
realization_gap = normalized_saved_gain - overall_peak_gain
total_expectation_gap = strategy_expected_saved_gain - overall_peak_gain
```

错位的主要来源包括：

1. Storage alias：多个逻辑 tensor 共享底层 storage，删除一个逻辑值未必释放独立分配。
2. Recompute transient：backward 中重算可能形成新的 live wave，使瞬时量抵消保存量收益。
3. Fixed frontier：参数、梯度、optimizer state 和 mandatory workspace 形成 activation-only 方法无法降低的下界。
4. Phase migration：峰值可能从 after-FW 边界迁移到 backward 或 optimizer。
5. Compiler/runtime offset：编译器 materialization、fusion、workspace 和 allocator 行为改变实际峰值。

冻结 EV-20 的 phase 结果支持上述目标错位存在于真实 workload 中：BERT-like、GPT2-like 和 ViT-B/16 的成功记录中，
measured peak 主要出现在 optimizer phase，而 ResNet-50 的成功记录峰值主要出现在 backward phase。也就是说，
只观察 saved activation 或 after-FW retained memory 无法完整解释最终 physical peak。

## 4 PeakAware 系统设计

PeakAware 的输入是 PyTorch 训练任务和一组物理预算；输出是每个预算下的 selected plan、测量结果、失败原因和
可复现 artifact。系统由九个阶段组成。

1. Joint capture：使用 AOTAutograd 捕获 forward/backward joint graph，并记录 graph key、plan identity 和
   runtime provenance。
2. Storage-aware IR：把 logical value、底层 storage、依赖、cost、phase 和 SAVE policy 分离建模。
3. Seed generation：生成 all-save、min-cut、block/greedy 等候选起点。
4. D0--D5 diagnosis：逐层计算 logical、storage、liveness、fixed frontier、compiler correction 和 runtime
   measurement 下的峰值解释。
5. SAVE repair：根据 peak live set 和 diagnostic hints 修复候选 SAVE 集合。
6. Pareto Top-K：按 estimated peak、step time 和多样性选择少量候选进入 expensive path。
7. Lowering：把候选计划 lower 为 AOT FW/BW executable，并记录 effective SAVE set。
8. Correctness validation：比较输出、梯度和参数更新，失败作为结果记录。
9. Complete-step measurement：测量 FW/BW/optimizer phase peak、overall peak、step time 和 budget headroom。

这个设计的关键不是某一个 seed，而是闭环：静态模型只负责缩小候选空间，最终选择由真实 executable 的完整 step
measurement 决定。EV-20 中 `aot_partition_runtime_candidate_rate=1.0`，成功记录的 selected plan 均带有
lowered-AOT runtime 证据；T7 显示四个 workload 的成功记录分别为 BERT-like 81、GPT2-like 39、ResNet-50 60、
ViT-B/16 20，失败类型均为预注册的 `InfeasibleBudgetError`。

## 5 实现

PeakAware 原型实现位于 `PeakAware/` 仓库中，实验使用 PyTorch `2.13.0+cu130`、CUDA `13.0` 和 NVIDIA RTX A6000。
冻结 workload manifest 见 T1：BERT-like-2L-64H 约 2.09M 参数，GPT2-like-2L-64H 约 6.54M 参数，ResNet-50 约
23.53M 参数，ViT-B/16 约 85.81M 参数。所有实验 microbatch 为 1，图像模型输入为 `1x3x224x224`，语言模型输入
sequence length 为 32。

实现中特别记录以下字段，以避免“不同策略标签运行同一 callable”的伪比较：

- `plan_id`、`plan_key`、`selected_saved_value_ids` 和 `selected_effective_saved_value_ids`；
- `selected_aot_partition_runtime` 与 fallback 状态；
- FW/BW/optimizer phase peak 与 phase time；
- correctness、error type、budget headroom 和 measured candidate count；
- environment fingerprint、workload entry id、budget manifest 和 artifact checksum。

Optimizer 不被编译进 joint graph，但作为 eager phase 进入完整 step measurement。这样做保持了 PyTorch 训练语义，
也让 fixed optimizer frontier 能够被纳入物理峰值判断。

## 6 实验方法

### 6.1 研究问题

本文评估五个研究问题。

- RQ-1：saved activation 目标与 complete-step physical peak 之间的错位是否可观测，主要根因是什么？
- RQ-2：storage/phase/fixed/compiler-aware 模型能否改善峰值预测？
- RQ-3：在紧预算下，PeakAware 的实测预算满足情况如何？
- RQ-4：在相同 workload 和预算下，selected plan 与内部/代理基线的 peak-throughput Pareto 关系如何？
- RQ-5：Top-K、编译/测量成本和 diagnostic hints 对结果有何影响？

### 6.2 Workload、backend 与预算

冻结 EV-20 覆盖四个 workload：BERT-like-2L-64H、GPT2-like-2L-64H、ResNet-50 和 ViT-B/16。每个 workload 在
AOT eager 和 Inductor 两个后端上运行，diagnostic hints 分别设置为 on/off。预算由 all-save measured peak 派生，
比例为 50%、65%、80%、95% 和 100%。矩阵 pass 数为 5，measurement repeats 为 5。

完整矩阵共 400 条 records：4 workloads x 2 backends x 2 hints variants x 5 budgets x 5 passes。失败记录不从分母
中删除；OOM、timeout、correctness failure、unsupported 和 infeasible 都是实验结果。EV-20 中实际失败类型均为
`InfeasibleBudgetError`。

### 6.3 指标

主指标包括：

- budget success：记录状态为 ok 且 measured allocated peak 不超过预算；
- measured allocated peak：完整 step 中 FW/BW/optimizer phase peak 的最大值；
- step time 和 samples/s：稳态 step time 及其倒数形式；
- prediction APE：以 measured peak 为分母的绝对百分比误差；
- phase accuracy：预测 dominant phase 与实测 dominant phase 是否一致；
- Top-K ranking：estimated ranking 与 measured ranking 的 Spearman/Kendall 相关性和 best-rank error；
- optimization cost：capture、IR build、analysis、executor build、candidate validation/measurement 的总时间。

### 6.4 Artifact 与验证

冻结 artifact 位于：

```text
artifacts/paper_full_matrix_combined_paired_5budget_5pass_r1/
```

该目录包含 raw records、derived summaries、F2--F10 图、T1--T8 表、manifest、checksums、environment lock 和
evidence gate report。最终 artifact verifier 在 `--require-frozen` 下通过，`error_count=0`、`warning_count=0`；
证据门禁 G-1--G-8 全部通过。

## 7 结果

### 7.1 RQ-3：预算满足与失败分布

EV-20 的 400 条记录中，200 条成功、200 条失败，总体成功率为 50%。所有成功记录均满足物理预算，
`budget_violation_count=0`。按 workload 和 hints variant 划分，预算成功率如下：

| Workload | Hints off | Hints on |
|---|---:|---:|
| BERT-like-2L-64H | 42/50 = 84% | 39/50 = 78% |
| GPT2-like-2L-64H | 20/50 = 40% | 19/50 = 38% |
| ResNet-50 | 30/50 = 60% | 30/50 = 60% |
| ViT-B/16 | 10/50 = 20% | 10/50 = 20% |

这些数字说明紧预算下的主要结果不是“所有点都能通过重计算解决”，而是不同 workload 的 activation-only
可行性差异很大。ViT-B/16 的 80 条失败和 GPT2-like 的 61 条失败都被保留为 `InfeasibleBudgetError`，这支持
PeakAware 报告不可行预算而不是从分母中删除失败点。

### 7.2 RQ-1：目标错位与 phase migration

成功记录的 dominant phase 呈现明显 workload 差异。BERT-like 的 81 条成功记录和 GPT2-like 的 39 条成功记录
均以 optimizer 为 measured peak phase；ViT-B/16 的 20 条成功记录也以 optimizer 为主；ResNet-50 的 60 条成功
记录则以 backward 为主。该结果直接说明 complete-step peak 不能只由 after-FW saved activation 决定。

D0--D5 分层分析进一步显示，raw/static 估计与 runtime measurement 之间存在显著 gap。BERT-like 的 raw 平均 APE
为 109.57%，GPT2-like 为 21.14%，ResNet-50 为 28.56%，ViT-B/16 为 52.68%。这些误差来自不同机制：BERT-like
主要由 rematerialization wave 和 workspace growth 解释；GPT2-like 主要由 rematerialization wave、workspace
growth 和少量 cost-model misrank 解释；ResNet-50 包含 rematerialization wave、cost-model misrank 和 unknown；
ViT-B/16 主要体现 fixed backward frontier 与 rematerialization wave。

### 7.3 RQ-2：峰值预测与校准

表 T4 显示，raw 峰值估计的总体平均绝对相对误差为 62.33%。引入 all-save residual/phase 校准后，总体平均误差
降至 6.54%，84.25% 的校准估计落在 10% 误差范围内。按 workload 看，校准后的平均 APE 为：

| Workload | Raw mean APE | Calibrated mean APE | Phase accuracy |
|---|---:|---:|---:|
| BERT-like-2L-64H | 109.57% | 12.59% | 75.31% |
| GPT2-like-2L-64H | 21.14% | 22.57% | 61.54% |
| ResNet-50 | 28.56% | 0.00% | 100.00% |
| ViT-B/16 | 52.68% | 3.38% | 75.00% |

这组结果支持两个结论。第一，纯 raw/static 模型不足以可靠约束物理峰值；第二，少量 all-save runtime
calibration 可以显著降低多数 workload 的预测误差。但该结果也有边界：GPT2-like 的校准误差略高于 raw，说明
calibration 不是无条件改进；D4/D5 的精度不能被表述为纯静态模型精度。

### 7.4 RQ-4：与内部/代理基线的 Pareto 对照

T2 显示 EV-20 中 all-save、block_checkpoint、torch_min_cut 以及 greedy 系列候选均有测量记录和正确性记录。
由于表中 baseline status 为 `proxy_or_internal`，本文将它们作为冻结 artifact 内部的 matched baseline/proxy
对照，不把这些数字外推为对官方 PyTorch 全实现的全面优越性声明。

在 200 个 matched baseline row 上，selected plan 相对 all-save 的几何平均 speedup 为 1.08x，平均峰值下降约
37.33 MB；相对 block_checkpoint 的几何平均 speedup 为 1.13x，平均峰值下降约 10.02 MB；相对 torch_min_cut
proxy/internal 对照的几何平均 speedup 为 1.28x，平均峰值下降约 18.64 MB。相对 greedy 组，几何平均 speedup
为 1.14x，但平均峰值差异仅约 0.33 MB。

这些结果应被解读为“在 EV-20 的 matched artifact 口径下，PeakAware selected plan 通常位于更好的
peak-throughput 区域”，而不是“全面支配所有 AC/SAC/min-cut 方法”。完整 Pareto 关系见 F2 和 F4。

### 7.5 RQ-5：Top-K、成本与 cache

EV-20 中每个成功 workload 的平均 candidate count 和 measured candidate count 均为 4，说明 Top-K path 实际将
候选测量规模控制在小集合内。候选时间排序的总体 Spearman 相关性为 0.459，Kendall 相关性为 0.402，平均
best-rank error 为 0.865。这表明静态 ranking 有一定信号，但不足以单独承担最终选择；Top-K measurement 不是
附加优化，而是系统可靠性的必要组成。

平均 optimization total time 约为 10.75 秒。按 workload，平均 optimization cost 和摊销步数如下：

| Workload | Mean optimization cost | Mean amortization steps |
|---|---:|---:|
| BERT-like-2L-64H | 2.16 s | 5813 |
| GPT2-like-2L-64H | 1.44 s | 37376 |
| ResNet-50 | 17.77 s | 2569470 |
| ViT-B/16 | 42.62 s | 13625 |

该结果是 mixed。对于部分 workload，优化成本可在较长训练中摊销；但 ResNet-50 的估计摊销步数过高，说明当前
实现的 optimization/measurement overhead 并不总是经济。论文不能把 cache 和 Top-K 写成无条件降低成本的结论，
而应写成控制搜索爆炸和保留 runtime correction 的工程机制。

### 7.6 Hints 消融

Diagnostic hints on/off 的 paired ablation 结果为 mixed。Hints off 的 200 条记录中 102 条成功，hints on 的
200 条记录中 98 条成功，成功率差为 -3 个百分点。100 个配对点中，41 个 on/off 均成功；7 个点在 success 上
改善，10 个点在 success 上退化，23 个点在 throughput 上改善，18 个点在 throughput 上退化，42 个点 inconclusive。
Search order changed pair count 为 0。

因此，当前证据不支持“diagnostic hints 稳定提高预算满足率或吞吐”的强声明。更谨慎且由证据支持的表述是：
diagnosis 提供了可解释的 root-cause evidence 和 repair 输入，但在 EV-20 的搜索面上，hints 对最终结果的影响
为 mixed，仍需进一步改进候选生成和 ranking 才能转化为稳定收益。

## 8 讨论

### 8.1 为什么失败样本重要

EV-20 一半记录失败，表面上看不像一个“漂亮”的系统结果，但它恰好反映了完整物理峰值预算问题的本质：并非
所有紧预算都能通过 activation recomputation 解决。当 fixed frontier、optimizer state 或 compiler workspace
已经接近或超过预算时，正确行为是报告 infeasible。把这些点删除会高估系统可靠性，也会掩盖 saved-memory 代理
目标与 physical peak 目标之间的根本差异。

### 8.2 Raw 模型与 calibration 的边界

D0--D3 诊断提供了可解释的静态近似，但 EV-20 的 raw APE 表明它不能直接作为硬预算判定器。All-save 校准显著
改善多数点的预测，但它依赖额外 runtime measurement。因此，本文的峰值模型应被描述为 storage/phase-aware
diagnosis 加上 runtime-assisted calibration，而不是纯静态预测器。

### 8.3 对 baseline 的谨慎解释

虽然 evidence gate G-1--G-8 全部通过，T2 的 status 仍提醒我们，EV-20 中的部分 baseline 是 artifact 内部或
proxy 口径。正文应始终使用 “matched internal/proxy baseline” 或在表格中明确 provenance，避免把实验结果写成
对所有 PyTorch 官方实现、所有 SAC policy 或所有 block checkpoint 划分的概括性结论。

### 8.4 对 hints 的负结果吸收

Hints 消融没有稳定正收益，这是一个需要保留的负结果。它说明“能解释收益缺口”和“能改变最终 Pareto 选择”之间
还有距离。对系统设计而言，这提示后续应把 root cause confidence、更强的 counterfactual repair 和 diversity
约束更紧密地接入候选生成，而不是只改变候选排序元数据。

## 9 局限性

本文实验边界如下。

1. Workload 只包含两个 torchvision 模型和两个小规格 transformer-like 模型；BERT-like/GPT2-like 不能代表标准
   BERT-Base 或 GPT-2。
2. 所有实验为静态 shape、microbatch 1、单设备训练；未评估 dynamic shape、pipeline/model parallel、FSDP/ZeRO、
   offload 或 activation compression。
3. 当前实现依赖 PyTorch AOTAutograd 和部分私有 ABI；跨 PyTorch 版本稳定性需要额外验证。
4. Measurement repeats 为 5，足以支撑当前 artifact gate，但后续投稿可增加独立进程数和 bootstrap CI。
5. Inductor 与 AOT eager 均被纳入矩阵，但本文没有单独声称 compiler backend 本身带来稳定收益。
6. Hints 和 Top-K 的效果为 mixed；当前证据支持它们作为诊断和控制搜索成本机制，不支持无条件收益声明。

## 11 结论

本文研究了选择性 activation recomputation 在完整训练物理峰值预算下的目标错位问题。实验表明，saved
activation、after-FW retained memory 和 complete-step allocated physical peak 之间存在显著差距；该差距可由
storage alias、rematerialization wave、fixed frontier、phase migration 和 compiler/runtime offset 等机制解释。

PeakAware 将这一问题转化为“解释 -> 修复 -> 下发 -> 实测选择”的闭环：先用 storage/phase/fixed/compiler-aware
模型诊断候选计划，再通过 Pareto Top-K lowering、正确性验证和 complete-step measurement 选择满足预算的
executable。在 EV-20 冻结矩阵中，系统在四个 workload、两个 backend 和五个预算比例下生成 400 条记录；所有成功
记录均满足预算，raw 峰值估计经 all-save 校准后平均 APE 从 62.33% 降至 6.54%。

同时，本文也保留负结果和边界：一半预算点不可行，hints 消融为 mixed，部分 workload 的优化成本难以摊销，且
baseline 结论仅限当前 matched artifact 口径。总体而言，PeakAware 说明了一个比“少保存 activation”更接近用户
约束的系统方向：以完整 step physical peak 为验收目标，用诊断和 runtime measurement 闭合 saved-memory 代理目标
留下的差距。
