# 论点证据账本

本账本是论文结果数字、artifact 路径和证据状态的唯一事实源。论点内容仍由
`../01_论点与故事线.md` 维护；本文档只回答“该论点现在有什么证据、还缺什么、
正文允许写到什么程度”。

## 1. 使用规则

1. 每个数字在正文、摘要、结论或答辩中出现时，必须绑定一个 `frozen` 的 `EV-*`。
2. `planned`、`smoke`、`provisional` 可指导实验和方法写作，不得用作效果结论；
   `invalid` 不得在任何效果论证中引用。
3. 每个 `EV-*` 冻结后不覆盖原文件。新 run 使用新 `run_id` 和 checksum；旧条目改为
   `superseded` 并指向替代条目。
4. 冻结条件同时要求：code commit、environment lock/fingerprint、原始 records、schema、
   导出脚本、manifest/checksum、失败样本和可重建的 derived summary。
5. 当“反证触发器”命中时，条目不得冻结为原声明；必须缩小 claim、解释条件或将
   该条目标记为 `invalid`。

| 冻结条件 | candidate pool 在查看实测结果前冻结；K 和多样性规则预注册；报 Spearman/Kendall、recall@K、P50/P90 regret；cold/warm 分开；只对有正 step-time 收益的点计算 break-even |
| 反证触发器 | 候选 frontier 在实测后调整；K=1 与较大 K 无区别或更好；cache key 错误复用计划；优化成本在目标训练长度内无法摊销 |
| 冻结后允许表述 | 只对实测可摊销点写“在 [steps] 后摊销”；弱 ranking 必须与 best-of-K 结果并列；无法摊销的点写 `not amortized` |

### EV-19 诊断/repair/Top-K/cache 消融

| 字段 | 内容 |
|---|---|
| 状态 | `planned` |
| 覆盖 | C-2/C-4/C-5、RQ-3/RQ-5；F-10、T-8 |
| 必需 artifact | 同一冻结 frontier 上 full 及 without storage normalization、without phase/fixed model、without hints/repair、without calibration、K=1、without cache 的配对记录 |
| 冻结条件 | 每次只改一项；消融共享测量协议和 candidate frontier；同时报 budget success、throughput、prediction error、regret 和 overhead；neutral/negative 不删除 |
| 反证触发器 | hints 只在 synthetic 上改变顺序，真实矩阵不改变计划/效果；calibration 改善误差但不改善预算选择；cache 只改善微基准；去掉组件后结果不变 |
| 冻结后允许表述 | 只将显著改变系统结果的组件写为实证必要；neutral 组件写为“实现支撑/未观测到主效果”，不包装成创新收益 |

## 6. 正文引用和反向审计

冻结后，正文使用类似“峰值误差的 P90 为 [数字]（EV-12/T-4）”的内部批注。投稿前
可去掉 `EV-*` 显示，但论文源文件必须保留可机器检查的映射。每次摘要/结论数字变更时执行
两向检查：

- 正向：正文数字 -> `EV-*` -> derived artifact -> raw artifact/checksum；
- 反向：每个核心 `C-*`/`RQ-*` -> 至少一个 `frozen EV-*` -> 图/表 -> 正文段落；
- 反证：失败、OOM、neutral hints、负 Pareto 点、弱 ranking、raw/calibrated 差异是否在正文或局限性中解释；
- 身份：baseline 是否为真实 AOT min-cut/block AC/SAC，模型是否为 T-1 中的 like 规格；
- 时间：raw records 是否生成于当前 plan-aware runtime 和冻结 commit，而不是对旧矩阵的离线补算。

任一项无法闭环时，对应数字从正文撤回，证据状态回退到 `provisional` 或标记为
`invalid`，不以“工程已验收”作为例外。
