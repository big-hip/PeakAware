# 执行排期与验收

本文档只管理任务依赖、时间、命令级动作、Gate 和返工条件，不改变 `C-*` 的边界，不保存最终
实验数字。实验矩阵以 `experiments/00_实验补强与测量协议.md` 为准，artifact 目录和最终复现入口
以 reproduction 文档为准，冻结事实只写入 evidence ledger。

## 1. 调度原则

1. 先修 baseline/runtime/measurement，再消耗 GPU 跑主矩阵；旧 64 条效果记录不进入排期复用。
2. 每个关键节点独立 Git 提交；提交前执行 diff 自审、测试和对应 Gate validator。
3. raw artifact 只追加不覆盖；失败 attempt、stderr、配置和环境同样保存。
4. GPU 任务按 canary -> 小批量 -> 全矩阵三级放量，每 10% slots 做一次质量审计。
5. 实现、实验执行、结果复核尽量由不同 agent/角色完成；复核者从 raw records 重建 summary。
6. 六周是稳健计划；压缩到四周时只并行独立任务，不删除核心覆盖或验证步骤。

## 2. Gate 依赖图

```text
G-0
 |-- G-1 baseline identity --\
 |-- G-2 workload naming ----+--> G-3 runtime --> G-6 measurement --> E-0
 |---------------------------/                                  |
                                                               G-5 budget
                                                                  |
                             aot_eager E-1/E-2/E-3/E-4 -----------+
                                                                  |
                             G-4 Inductor matrix ------------------+
                                                                  |
                             E-5/E-6/E-7/E-8/E-9 ------------------+
                                                                  v

```

`G-1/G-2/G-3/G-6` 是 GPU 主矩阵的硬前置；`G-5` 在 all-save 标定后通过；`G-4` 只有四架构
Inductor 正式矩阵完成才通过，不能由 smoke 替代。

## 3. 六周主计划

### 第 1 周：冻结身份、baseline 和测量器

**目标 Gate**：`G-0/G-1/G-2/G-3/G-6`。

**任务**：

- 审计当前 registry，将论文和 artifact display name 固定为 ResNet-50、ViT-B/16、
  BERT-like-2L-64H、GPT2-like-2L-64H；补模型规格导出；
- 接入真实 PyTorch AOT min-cut，保留 `min_cut_proxy` 但从主 baseline 枚举移除；
- 为四架构定义真实 block region，接入 SAC policy，确保 backend 不支持时返回 `unsupported`；
- 为所有方法增加 strategy provenance、plan identity、FW/BW executable identity 和 runtime adoption marker；
- 实现 CUDA Event phase/overall timing、同步 wall clock、allocated/reserved peak、OOM/timeout 分类；
- 增加至少 3-step correctness、gradient/parameter/RNG/alias 检查；
- 完成 `E-0` 四架构双 backend qualification。

**命令级任务**：以下命令是验收入口；若脚本尚无相应参数，先实现 CLI 并补测试，不得手工改 JSON。

```bash
conda run -n torch2.13-gpu env PYTHONPATH=. python -m pytest -q tests
conda run -n torch2.13-gpu python scripts/inspect_external_baselines.py
conda run -n torch2.13-gpu python scripts/run_experiments.py --help
conda run -n torch2.13-gpu python scripts/run_sac_baseline_matrix.py --help
```

建议新增并冻结的入口：

```bash
conda run -n torch2.13-gpu python scripts/qualify_publication_runtime.py \
  --tasks resnet50,vit_b_16,bert_base,gpt2 \
  --backends aot_eager,inductor --methods all_save,pytorch_min_cut,block_ac,sac,peakaware \
  --processes 2 --warmup auto --repeats 20 --output-root artifacts/paper/<run_id>/qualification
```

**产物**：baseline provenance、四模型 config manifest、qualification raw records、correctness report、
Event/wall-clock 对照、完整测试日志。

**验收**：

- 真实 min-cut 的 provenance 指向 PyTorch partitioner，不是 mandatory-only proxy；
- block AC 的 region 与模型 block 对应；SAC policy 可审计；
- 不同方法的 runtime identity 不同，且没有静默 whole-model fallback；
- 四架构双 backend 均有资格记录，失败明确为 `unsupported` 或错误状态；
- 完整测试通过，新增 baseline/measurement/correctness 测试覆盖成功和失败路径。

**返工条件**：出现共享 callable、runtime marker 为空、模型名与 config 不一致、正确性容差事后放宽、
Event/wall-clock 窗口不一致，停止后续 GPU 任务。

**建议提交**：`feat: integrate publication baselines and measurement protocol`。

### 第 2 周：冻结预算并完成 AOT 核心矩阵

**目标 Gate**：`G-5`，推进 `G-3`；完成 `E-1/E-2/E-3/E-4` 的 `aot_eager` 部分。

**任务**：

- 用五个独立进程标定每个 canonical configuration 的 all-save `P_ref`；
- 生成并冻结 50/65/80/95/100% 预算表和随机运行顺序；
- 在最多 3 个 tuning 进程上按统一候选/时间上限选择各方法 policy，冻结后再启动 5 个 held-out
  evaluation 进程；
- 先运行四架构 65% canary，再分批执行 AOT 核心矩阵；
- 每完成 10% slots 检查 schema、plan identity、重复 run ID、零峰值、失败分类和 baseline coverage；
- 从 raw records 重建临时 summary，仅用于质量控制，不写论文数字。

**命令级任务**：

```bash
conda run -n torch2.13-gpu python scripts/calibrate_publication_budgets.py \
  --tasks resnet50,vit_b_16,bert_base,gpt2 --backend aot_eager \
  --processes 5 --ratios 0.50,0.65,0.80,0.95,1.00 \
  --output artifacts/paper/<run_id>/manifests/aot_budgets.json

conda run -n torch2.13-gpu python scripts/run_publication_matrix.py \
  --manifest artifacts/paper/<run_id>/manifests/aot_budgets.json \
  --methods all_save,pytorch_min_cut,block_ac,sac,peakaware \
  --processes 5 --warmup auto --repeats 20 --randomize-order \
  --output-root artifacts/paper/<run_id>/raw/aot_eager

conda run -n torch2.13-gpu python scripts/validate_publication_records.py \
  artifacts/paper/<run_id>/raw/aot_eager
```

这些 publication 脚本是本周交付物；在它们实现前，可复用 `run_experiments.py` 做 canary，但不得用
现有单进程/绝对预算 CLI 直接宣称主矩阵达标。

**产物**：`P_ref` 原始标定、预算 manifest、顺序 seed、AOT raw records、失败 attempts、质量审计日志。

**验收**：四架构、五预算、四个预算感知方法和 all-save reference 的评价 slot 可由 manifest 枚举；
每个 slot 有 5 个 held-out 进程、至少 20 repeats 或明确失败状态；tuning/evaluation seed 不重叠；
预算不是按候选自身峰值计算；旧 records 未被覆盖或混入。

**返工条件**：缺失超过 10%、某 baseline coverage 异常、方法顺序未保存、预算在运行后改变、
allocator/温度表现出系统顺序偏差。返工使用新 attempt，不删除旧 attempt。

**建议提交**：`exp: freeze aot publication matrix`。

### 第 3 周：完成四架构 Inductor 主矩阵

**目标 Gate**：`G-4`；完成 `E-1/E-2/E-3/E-4` 的 Inductor 部分。

**任务**：

- 独立标定 Inductor `P_ref`，不能复用 AOT 预算字节值；
- 运行四架构 95% canary，确认编译完成、runtime identity、workspace 和 steady-state；
- 在独立 tuning cohort 冻结各方法 policy，评价进程不得依据实测结果重选；
- 放量至五预算核心矩阵，保存 compile/autotune 与 steady-state 分离时间；
- 对 timeout、编译失败和 OOM 分类，检查是否为方法行为而非基础设施；
- 每日从 raw records 做 coverage 和漂移审计，必要时隔离 GPU 或降低并发，不减少进程重复数。

**命令级任务**：

```bash
conda run -n torch2.13-gpu python scripts/calibrate_publication_budgets.py \
  --tasks resnet50,vit_b_16,bert_base,gpt2 --backend inductor \
  --processes 5 --ratios 0.50,0.65,0.80,0.95,1.00 \
  --output artifacts/paper/<run_id>/manifests/inductor_budgets.json

conda run -n torch2.13-gpu python scripts/run_publication_matrix.py \
  --manifest artifacts/paper/<run_id>/manifests/inductor_budgets.json \
  --methods all_save,pytorch_min_cut,block_ac,sac,peakaware \
  --processes 5 --warmup auto --max-warmup 30 --repeats 20 \
  --randomize-order --output-root artifacts/paper/<run_id>/raw/inductor

conda run -n torch2.13-gpu python scripts/validate_publication_records.py \
  artifacts/paper/<run_id>/raw/inductor
```

**产物**：Inductor budget manifest、编译日志、raw records、plan artifacts、GPU/driver/Inductor 配置、
coverage report。

**验收**：四架构均有正式 warmup/repeats/phase/overall peak；all-save 与四种方法身份可区分；失败
slot 不被 smoke 替代；compile time 不混入稳态 step time。

**返工条件**：任一架构只有 `top_k=1` smoke、所有方法选中同一 executable、最后五个 warmup 仍
持续下降、Inductor cache 污染 cold 条件，均不得通过 `G-4`。

**建议提交**：`exp: freeze inductor publication matrix`。

### 第 4 周：诊断、消融、开销与稳健性

**目标实验**：`E-5/E-6/E-7/E-8/E-9`。

**任务**：

- 扩充根因合成集到八类、每类至少三个参数化实例；
- 在真实错位点运行 hints on/off 配对，不把 pass/repeats 当独立 workload；
- 运行组件消融、Top-K `{1,3,5,10}`、cold/warm cache 和 fixed-frontier 矩阵；
- 抽取 65%/95% 点反转方法顺序并更换顺序 seed；
- 在每架构至少两个额外 microbatch/sequence 点运行 `E-4` 扩展矩阵；
- 记录负结果：hints neutral、ranking 弱、不可行预算、SAC frontier trade-off 均不得删除。

**命令级任务**：

```bash
conda run -n torch2.13-gpu python scripts/run_root_cause_benchmark.py \
  --output-json artifacts/paper/<run_id>/raw/root_causes.json
conda run -n torch2.13-gpu python scripts/run_hint_effectiveness_benchmark.py \
  --output-json artifacts/paper/<run_id>/raw/hint_effectiveness.json
```

`run_root_cause_benchmark.py` 当前产物已同时包含 synthetic labels、predictions 和汇总 accuracy。若扩展
为外部标注集，使用现有 `evaluate_root_causes.py --predictions <path> --labels <path> --output-json
<path>`，不要把合并产物误传给不存在的 `--input-json` 参数。

建议新增统一消融入口：

```bash
conda run -n torch2.13-gpu python scripts/run_publication_ablations.py \
  --manifest artifacts/paper/<run_id>/manifests/ablations.json \
  --processes 5 --repeats 20 --output-root artifacts/paper/<run_id>/raw/ablations
```

**产物**：合成 ground truth、真实 diagnosis evidence、hints 配对记录、消融矩阵、Top-K/cache
开销、顺序偏差和扩展 workload raw records。

**验收**：每个消融只改变一个目标组件；真实诊断不声称唯一因果；cache cold/warm identity 匹配；
amortization 的分子分母可重建；hints 若未改变方案则明确记为 neutral。

**返工条件**：消融代码路径实际相同、合成标签由被测诊断器反推、warm cache 使用不同 graph/plan
identity、只报告预测误差而不报告最终 ranking/plan，均需返工。

**建议提交**：`exp: freeze diagnosis and ablation evidence`。

### 第 5 周：冻结证据、统计和出版图表

**目标 Gate**：`G-7/G-8`。

**任务**：

- 锁定 raw artifact，生成 manifest、SHA-256、环境 lock 和 schema version；
- 由独立复核者从 raw records 重建 derived summaries；
- 执行配对统计、bootstrap CI、几何平均、失败率和 Top-K regret；
- 将每个可用结果登记为 `EV-*`，无证据或有反证的 `C-*` 不升级；
- 从冻结数据自动生成 `F-*`/`T-*`，检查无手填数字、色盲和灰度可读性；
- 进行一次“寻找反证”的审计：按架构、backend、预算、失败状态拆分总体结论。

**命令级任务**：

```bash
conda run -n torch2.13-gpu python scripts/validate_publication_records.py artifacts/paper/<run_id>/raw
conda run -n torch2.13-gpu python scripts/build_publication_summaries.py \
  --raw-root artifacts/paper/<run_id>/raw --output-root artifacts/paper/<run_id>/derived
conda run -n torch2.13-gpu python scripts/generate_publication_figures.py \
  --manifest artifacts/paper/<run_id>/manifest.json --output-root artifacts/paper/<run_id>/figures
conda run -n torch2.13-gpu python scripts/verify_publication_artifact.py artifacts/paper/<run_id>
```

**产物**：immutable raw、derived summaries、evidence ledger、manifest/checksums、PDF/SVG/PNG 图表、
CSV/LaTeX 表格、重建日志。

**验收**：每个正文候选数字映射一个 `EV-*`；`EV-*` 映射 raw 字段和 checksum；raw/static 与
calibrated 分开；旧 invalid 数字未混入；从空 derived/figures 目录可一条命令重建。

**返工条件**：统计把 repeats/hints 当独立样本、预算失败被过滤、图表由手工表生成、checksum
不匹配、摘要与 ledger 数字不一致，立即撤销冻结状态并重建。

**建议提交**：先 `docs: freeze thesis evidence ledger`，再 `feat: generate publication figures`。

### 第 6 周：正文、Artifact 演练和答辩

**目标 Gate**：`G-9`，论文级完成定义。

**任务**：

- 按章节蓝图写作，先结果/方法，再引言/摘要/结论；所有结果数字从 `EV-*` 引用；
- 为 `RQ-1`--`RQ-5` 各写结论、反例、局限和适用边界；
- 在干净 clone/新环境运行 smoke reproduction，再抽取一个完整主点复现；
- 完成图表打印、灰度、字体、引用和模型命名审计；
- 演练答辩，重点回答真实 min-cut 身份、旧矩阵失效、fixed frontier、calibration 成本和负结果；
- 冻结论文 PDF、Artifact README、commit/tag 和校验和。

**命令级任务**：

```bash
git diff --check
rg -n 'BERT-Base|GPT-2([^ -]|$)|torch_min_cut|64/64|59,189,456' docs/论文
conda run -n torch2.13-gpu env PYTHONPATH=. python -m pytest -q tests
conda run -n torch2.13-gpu python scripts/verify_publication_artifact.py artifacts/paper/<run_id>
```

`rg` 命中不是自动失败，但每个命中都必须是禁止表述说明、历史 invalid 说明或已由标准规格/真实
baseline 解锁的正文内容。

**产物**：完整草稿/PDF、Artifact 包、复现日志、答辩稿、风险问答和冻结 tag。

**验收**：`G-0`--`G-9` 全通过；每个 `C-*` 有 frozen `EV-*` 或被明确降级；干净环境复现成功；
论文、图表、答辩三处数字一致；无 proxy 冒充真实 baseline。

**返工条件**：摘要包含未冻结数字、结论超出四架构/静态 shape/单设备边界、Artifact 缺 raw data、
命令依赖本机绝对缓存、答辩无法从 plan identity 证明真实执行，均不得提交终稿。

**建议提交**：`docs: complete thesis draft and artifact rehearsal`。

## 4. 可压缩四周方案

压缩只通过并行和缩短等待，不改变核心协议：

| 压缩周 | 并行工作流 | 不可压缩的串行点 |
|---|---|---|
| 第 1 周 | baseline/runtime、measurement、workload manifest 三组并行 | 合并后统一完成 `E-0` |
| 第 2 周 | AOT 与 Inductor 在不同 GPU/时段运行；文稿先写背景/方法 | 各 backend 必须先独立 `P_ref` 和 canary |
| 第 3 周 | 诊断/消融、统计脚本、图表模板并行 | derived 只能读取已冻结 raw |
| 第 4 周 | evidence 复核、写作、Artifact 演练、答辩并行 | `G-7 -> G-8 -> G-9` 顺序不变 |

四周方案要求至少一块 GPU 专用于正式矩阵，调试任务不能污染其环境。若第 2 周结束时 `G-4` 未通过，
立即恢复六周计划；不得把两模型 Inductor smoke 宣称为完成。

## 5. 每日运行看板

每个 GPU 批次维护以下字段，不在本文件写结果值：

| 字段 | 用途 |
|---|---|
| `run_id / attempt_id / commit` | 防止覆盖和混合代码版本 |
| `E-* / Gate / owner / reviewer` | 明确任务和独立复核 |
| `expected_slots / completed_slots` | 监控矩阵 coverage |
| `ok / violation / oom / timeout / correctness / unsupported / infra` | 监控失败分类 |
| `last_schema_audit / last_checksum` | 防止后期才发现坏数据 |
| `GPU / start / ETA / temperature note` | 排查硬件与顺序漂移 |
| `blocker / next action` | 触发返工或重新派发 |

状态只允许 `pending/running/review/accepted/rework/invalid`。`accepted` 必须有 reviewer 和 validator
日志；`invalid` 数据保留但不再派生论文结果。

## 6. 每个关键提交的 Definition of Done

提交前统一执行：

```bash
git status --short
git diff --check
git diff
conda run -n torch2.13-gpu env PYTHONPATH=. python -m pytest -q tests
```

并按提交类型追加：

- baseline/runtime：真实 identity 集成测试、proxy 禁入主矩阵测试、fallback/unsupported 测试；
- measurement：Event/wall-clock、phase/overall peak、OOM/timeout、独立进程测试；
- experiment：manifest coverage、schema、重复 ID、checksum、失败分母 validator；
- figures/evidence：从 raw 重建、数字反向追踪、图表输入 checksum；
- docs：Markdown 链接、术语、模型名称、禁止 claim 和 `EV-*` 引用审计。

提交必须只包含该节点相关代码、测试、文档或 immutable artifact manifest。完整 raw 数据若因体积不进
Git，提交 checksum、下载/归档位置和最小 smoke sample；不能继续让 `artifacts/` 完全不可获得。

## 7. 总体验收与降级决策

### 可进入完整论文叙事

- `G-1`--`G-7` 均通过；
- `E-3/E-4` 有四架构、双 backend、五预算、真实 baseline 的 frozen evidence；
- `C-1`--`C-5` 各有支持证据，并公开不支持或相反的点；
- 读者可从 raw records 重建预算满足、Pareto、误差和开销结论。

### 必须降级为原型/诊断论文

出现以下任一情况：

- 真实 min-cut/SAC/block 未接入，只剩 proxy 比较；
- 四架构当前 runtime 或 Inductor 主矩阵未完成；
- 紧预算下 PeakAware 没有可靠性或 Pareto 改善，且无法形成有边界的负结果贡献；
- hints 不改变真实决策且峰值模型只在 D5 后准确；
- artifact 无法复现或方法 identity 无法审计。

降级时保留 `C-1/C-2/C-3` 中被证据支持的部分，删除或收缩 `C-4/C-5`，题目和摘要改为目标错位
刻画、诊断和可执行原型，不以旧 64 条结果填补缺口。
