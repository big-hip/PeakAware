# 术语与口径

## 1. 内存术语

| 中文 | 英文/字段 | 定义 |
|---|---|---|
| 保存激活 | saved activation | 前向结束后跨越 FW/BW 边界、供 backward 使用的 activation |
| 逻辑值字节 | logical value bytes | tensor 视图看到的字节，不保证对应独立物理分配 |
| 物理存储 | storage | alias/view 共享的底层分配；SAVE 决策收益按 storage 归一化 |
| 前向后保留量 | after-FW retained | forward 结束、backward 开始前仍保留的 activation storage |
| 重计算瞬时量 | recompute transient | backward 中因 rematerialization 同时存活的临时 storage |
| 固定前沿 | fixed frontier | 参数、buffer、梯度、optimizer state/temporary 和 mandatory workspace 下界 |
| 物理峰值 | physical peak | 完整 step 中 `max(FW peak, BW peak, optimizer peak)` |
| allocated peak | `*_peak_bytes` | `torch.cuda.max_memory_allocated()` 口径 |
| reserved peak | `*_reserved_peak_bytes` | allocator reserved 口径，只作碎片和保留池分析 |

论文默认“峰值”指 allocated physical peak；使用 reserved 时必须在图题和正文中显式标注。

## 2. 执行模式

| 名称 | 准确定义 |
|---|---|
| eager all-save | 原模型 forward/backward，无 AOT SAVE 策略 |
| block AC | 显式 checkpoint region，边界固定 |
| SAC | PyTorch Selective Activation Checkpoint policy |
| AOT min-cut | AOTAutograd joint graph 上由 PyTorch partitioner 产生的真实 min-cut 计划 |
| min-cut proxy | 当前仓库 mandatory-only SAVE proxy；G-1 前不得简称为真实 min-cut |
| PeakAware | 统一 seeds、诊断、repair、Top-K 和实测选择后的计划 |
| lowered-AOT runtime | 最终 executable 直接调用候选 FW/BW GraphModule |
| checkpoint fallback | unsupported lowered ABI 时 whole-model checkpoint adapter |
| compiled step | compiled/lowered FW/BW 加 eager optimizer phase，不表示 optimizer 被编译进 joint graph |

图例、表格和 artifact 中必须区分 `min_cut_proxy` 与 `pytorch_min_cut`。

## 3. 模型命名

| 当前 registry 名 | 当前实际规格 | 论文冻结前名称 |
|---|---|---|
| `resnet50` | torchvision ResNet-50 | ResNet-50 |
| `vit_b_16` | torchvision ViT-B/16 | ViT-B/16 |
| `bert_base` | 2 layers、hidden 64、4 heads | BERT-like-2L-64H |
| `gpt2` | 2 layers、width 64、4 heads、seq 32 | GPT2-like-2L-64H |

只有补跑标准 config 后才能使用 BERT-Base、GPT-2 Small/Medium 等标准名称。T-1 必须列出参数量、
层数、hidden、heads、sequence/image size、batch、dtype、optimizer 和 loss。

## 4. 误差与校准

设估计峰值为 `P_hat`，实测峰值为 `P`：

```text
signed_error = P_hat - P
absolute_error = |P - P_hat|
relative_error = (P_hat - P) / P
APE = |P_hat - P| / P
MAPE = mean(APE)
```

论文主误差以实测峰值 `P` 为分母，并同时报告 mean、P50、P90 和 max；低估与高估方向不能被
绝对值隐藏。现有 artifact 中以 `P_hat` 为分母的 `abs(relative_error)` 保留为
`legacy_estimate_normalized_error`，不得与论文主 MAPE 混用。

- `raw/static`：不读取当前 workload 的 runtime baseline；
- `all-save residual calibrated`：使用一次 all-save measured peak 修正固定偏移；
- `all-save phase calibrated`：使用同 workload 的 all-save dominant phase；
- `D4/D5`：compiler/runtime correction，不属于纯静态模型。

任何 calibrated 图必须并列 raw 图或 raw 数字，并写明 calibration cost。

## 5. 策略收益差距

```text
strategy_expected_saved_gain
normalized_saved_gain
after_fw_gain
overall_peak_gain

strategy_estimation_gap = strategy_expected_saved_gain - normalized_saved_gain
realization_gap = normalized_saved_gain - overall_peak_gain
total_expectation_gap = strategy_expected_saved_gain - overall_peak_gain
```

没有公开 strategy expectation 的 baseline 将该字段标为 `unavailable`，不能补零。

## 6. 性能与 Pareto

- 固定 batch：在 `physical_peak <= B` 下最小化 steady-state step time；
- 固定任务：在预算下最大化 samples/s 或 tokens/s；
- speedup：`baseline_step_time / candidate_step_time`；
- strict Pareto win：peak 更低且吞吐更高；
- weak Pareto win：peak 不高且吞吐不低，至少一个严格改善；
- dominated：存在另一个方案 peak 不高、吞吐不低且至少一个严格改善。

不同模型的 samples/s 不直接求总和；可以对 matched baseline speedup 求几何均值。旧 artifact 的算术均值
保留为历史证据，正式论文在 evidence ledger 中明确最终聚合方式。

## 7. 测量统计

- warmup 与 measurement 分开；
- 每个方案至少 20 个 steady-state repeats，关键主结果建议 50；
- 报告 median、P10/P90，建议增加 bootstrap 95% CI；
- CUDA 每阶段计时优先使用 CUDA Event，并与同步 wall-clock 做一次一致性检查；
- 每个候选在独立状态副本或隔离 worker 中测量；
- correctness failure、OOM、timeout 都是结果，不从分母中静默删除；
- compile/optimization time 与 steady-state step time 分开。

## 8. D0--D5

| Level | 引入因素 | 论文作用 |
|---|---|---|
| D0 | logical saved values | 策略表面预期 |
| D1 | storage/alias normalization | 真实可释放 storage |
| D2 | recompute transient/liveness | backward 重计算波 |
| D3 | fixed frontier/phase composition | 完整静态 step peak |
| D4 | compiler correction | 编译器物化和 workspace |
| D5 | runtime measurement | 物理实测 ground truth |

D0--D3 可以称静态诊断；D4/D5 必须称校正或实测层。

## 9. 证据状态

| 状态 | 含义 |
|---|---|
| `planned` | 只有设计，无运行 |
| `smoke` | 证明链路可用，不支持主结论 |
| `provisional` | 有结果，但代码/协议/模型/baseline 尚未冻结 |
| `frozen` | commit、环境、raw artifact、checksum 和字段均冻结 |
| `superseded` | 被新 run 替代，只保留历史 |
| `invalid` | 违反协议或发现错误，不得引用 |

正文只允许引用 `frozen` 证据；方法章节可引用代码和测试，不把 smoke 当效果结论。
