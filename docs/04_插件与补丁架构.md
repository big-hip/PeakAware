# PeakAware 插件与补丁架构

## 1. 原则

PeakAware 采用：

```text
stable core contract first
plugin only for proven replacement points
scoped patch_method only when no public extension point exists
```

本章属于 M2 工程化阶段。M0/M1 使用 `contracts.py` 和构造函数参数直接连接核心模块，不要求
Registry。只有某个能力已有至少两个真实实现、需要第三方扩展或需要隔离 PyTorch 版本时，才提升为
插件接口。补丁用于截获 PyTorch 内部缺失的 hook，不能把全局 monkey patch 当成默认集成方式。

## 2. 插件类型

```python
class PeakAwarePlugin(Protocol):
    name: str
    version: str

    def register(self, registry: PluginRegistry) -> None: ...
```

M2 插件可以注册：

- `CaptureBackend`；
- `IRPass`；
- `FixedMemoryProvider`；
- `CostProvider`；
- `CandidatePolicy`；
- `SearchStrategy`；
- `PartitionBackend`；
- `RuntimeValidator`；
- `PlanDiagnostic`；
- `RootCauseRule`；
- event hook；
- `PatchSpec`。

同一插件不得隐式修改另一个插件的对象。跨插件通信使用 registry 中的显式 service 或 event。
默认 Fixed Frontier、liveness、simulator 和 search engine 仍是核心实现，不通过 service lookup
互相调用；插件只能替换其公开 provider/backend，或以只读方式观察阶段产物。

## 3. Registry

```python
class PluginRegistry:
    def register_service(self, kind, name, service, *, priority=0): ...
    def register_hook(self, event, callback, *, priority=0): ...
    def register_patch(self, spec: PatchSpec): ...
    def resolve(self, kind, name=None): ...
    def freeze(self) -> RegistrySnapshot: ...
```

Registry 在请求规范化后冻结，运行中不允许动态增加插件，避免搜索候选间环境不同。

冲突策略：

- service name 重复默认报错；
- hook 按 priority 和注册顺序执行；
- patch 组成 wrapper chain，不允许静默覆盖；
- exclusive service 只能有一个 active implementation。

## 4. Event Hooks

推荐事件：

```text
before_request_validation
after_request_validation
before_joint_capture
after_joint_capture
after_ir_build
after_legality_analysis
after_fixed_frontier
after_baseline_analysis
before_cost_query
after_cost_query
before_search
after_plan_simulation
after_plan_diagnostic
after_search
before_partition
after_partition
after_inductor_compile
after_runtime_measure
after_runtime_diagnostic
on_fallback
```

Hook 输入默认只读。需要改变结果时，callback 返回显式 replacement 或 decision object；禁止
原地修改共享 IR。

## 5. Patch Method

### 5.1 PatchSpec

```python
@dataclass(frozen=True)
class PatchSpec:
    owner: str
    target_module: str
    target_attribute: str
    wrapper: Callable
    torch_version_range: str
    expected_signature: str | None
    priority: int = 0
    failure_policy: str = "fail_closed"
```

Wrapper 采用 around 形式：

```python
def wrapper(next_fn, *args, **kwargs):
    before(...)
    result = next_fn(*args, **kwargs)
    return after(result)
```

这样多个插件可以组合：

```text
wrapper A -> wrapper B -> original -> wrapper B -> wrapper A
```

### 5.2 PatchSession

```python
with PatchSession(registry.patch_specs, environment):
    captured = capture_joint_graph(...)
```

必须保证：

- 进入时验证 PyTorch 版本和目标签名；
- 记录原始对象 identity；
- 防止重复 patch；
- 异常时在 `finally` 中恢复；
- Session 退出后验证恢复成功；
- 写入 owner、target、version 和结果日志。

### 5.3 并发边界

Python method patch 通常是进程全局的，不保证线程隔离。存在 patch 的捕获或编译任务默认在
独立进程执行；同一进程同时只能有一个 active `PatchSession`，由全局锁保护。

## 6. 允许的 Patch 点

第一版允许：

- 截获 AOTAutograd `partition_fn` 输入以保存 pre-partition joint graph；
- 读取 partition 后 FW/BW graph；
- 采集当前版本可验证的 Inductor IR/scheduler 摘要。

第一版禁止：

- 长期替换 `torch.Tensor` 核心行为；
- 修改 autograd engine 全局执行语义；
- 在用户训练循环外永久 patch optimizer；
- patch 后不恢复；
- 未声明版本范围地访问私有 API。

## 7. 不应使用 Patch 的场景

- 自定义算子 FakeTensor：使用 `torch.library.register_fake`；
- Costmodel：实现 `CostProvider`；
- 搜索算法：实现 `SearchStrategy`；
- IR 分析：实现 `IRPass`；
- 模型任务：注册 `TrainingTaskSpec`；
- runtime 指标：使用 `torch.profiler`、CUDA Event 和公开 memory API，不通过 patch 采集。

## 8. 内置插件（M2）

### JointCapturePlugin

职责：作用域化截获 pre-partition joint graph，收集版本和 guards。若目标签名不匹配，明确
报 `UnsupportedTorchVersionError`。

### LegacyCostmodelPlugin

职责：注册现有 Costmodel 的 adapter，不修改 Costmodel 原文件。

### ProfileDBPlugin

职责：注册精确查询、邻近 shape 插值和 profile collector。

### PeakAnalysisPlugin

职责：为实验替换或扩展 Fixed Frontier、storage liveness、peak explanation provider；默认核心实现
仍由 `memory/` 直接提供。

### PlanDiagnosticPlugin

职责：注册 D0--D5 反事实分析、峰值快照比较、root-cause rules 和 repair-hint mapper。该插件
在 M2 默认启用，对所有策略生效，不只观察 min-cut；M1 的基础 wave/fixed/alias 诊断不依赖它。

### MinCutSeedPlugin

职责：包装或调用当前 PyTorch min-cut 生成 seed；不得把其 saved-memory budget 当作最终物理
预算。

### InductorCorrectionPlugin

职责：在受支持版本采集 fusion/materialization/workspace 摘要；不受支持时返回低置信度并
回退到 Top-K 实测。

## 9. 插件配置

```yaml
plugins:
  - name: joint_capture
    enabled: true
  - name: legacy_costmodel
    enabled: true
    hardware: Ascend910B
  - name: profile_db
    enabled: true
    path: artifacts/profiles.sqlite
  - name: peak_analysis
    enabled: true
  - name: plan_diagnostic
    enabled: true
  - name: inductor_correction
    enabled: false
```

影响 capture/decomposition 的插件进入 capture cache key；改变 alias、legality、region、liveness
或 fixed frontier 的插件进入 analysis cache key；Cost、search、partition、dry-run、Inductor 和
validation 插件进入 executable cache key。上游 key 变化级联失效下游缓存，仅更换 observe-only
报告插件不应触发重新捕获、分析或编译。

## 10. Failure Policy

`fail_closed`：捕获、legality、partition 和 correctness 插件默认使用。失败时停止该候选或请求。

`degrade`：Costmodel、Inductor correction 和可视化插件可以降级到 fallback，并降低 confidence。

`observe_only`：日志、trace 和报告插件失败不改变算法结果，但必须记录错误。

## 11. 测试

必须覆盖：

- patch 进入/退出后对象 identity 恢复；
- wrapper priority 和调用顺序；
- 原函数抛异常时恢复；
- 版本不匹配时 fail closed；
- 重复 patch 检测；
- plugin service 冲突；
- hook replacement 的不可变语义；
- 子进程退出后无全局污染。

## 12. 论文定位

插件框架是系统贡献和可复现性基础，不应单独包装为算法创新。它的论文价值在于支持：

- 相同 Joint IR 下替换 cost source；
- 相同搜索器下比较不同 peak model；
- 在不同 PyTorch 版本中隔离私有 API；
- 以插件消融证明每个分析层的实际收益。
