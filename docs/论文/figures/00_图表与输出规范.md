# 图表与输出规范

本文档只定义图表的数据契约、视觉编码和出版验收。实验如何运行由
`experiments/00_实验补强与测量协议.md` 维护，图中数字及 artifact 来源由
`evidence/00_论点证据账本.md` 维护。所有正文图表只能从 `frozen` 的 `EV-*` 生成。

## 1. 统一数据单元

- 主抽样单元是唯一 workload configuration：模型规格、输入 shape、microbatch、dtype、optimizer
  和 loss 相同；compiler mode 与相对预算定义预注册实验 cell，不制造新的 workload 样本。
- 策略、hints on/off 和 matrix pass 是 cell 内配对条件，独立进程/seed 是重复测量，均不得扩大
  workload `N`。record 主键至少含 `run_id/config_fingerprint/budget_ratio/compiler_mode/strategy/
  independent_run_id/repeat_id`；跨 cell 汇总使用 workload-clustered bootstrap。
- 每次独立进程运行的 raw repeats 全部保留。预算违约用该运行的最大 allocated peak
  判定，稳态性能默认用 median。
- 跨 workload 的 speedup 用几何平均，并同时报告逐点分布和配对胜/平/负。
- 误差主口径是 `abs(estimated_peak_bytes - measured_peak_bytes) / measured_peak_bytes`；
  旧的 estimate-normalized 字段只能以 `legacy_estimate_normalized_error` 出现。
- `allocated peak`、`reserved peak`、logical saved 和 storage-normalized saved 不得共用一条未注明
  的“memory”轴。raw 和 calibrated 结果必须并列，不得只画较好的一组。

## 2. 视觉系统

### 2.1 颜色、线型与 marker

使用 Okabe--Ito 色板，策略颜色在所有图中固定；颜色之外必须再用 marker 或线型
编码，以便灰度打印和色觉异常读者识别。

| 策略/语义 | 颜色 | marker | 线型 |
|---|---:|---:|---|
| eager all-save | `#000000` | `o` | solid |
| block AC | `#E69F00` | `s` | dashed |
| SAC | `#CC79A7` | `P` | dash-dot |
| AOT min-cut | `#0072B2` | `^` | dashed |
| PeakAware | `#009E73` | `D` | solid |
| raw/static estimate | `#56B4E9` | `x` | dotted |
| calibrated estimate | `#D55E00` | `v` | dash-dot |
| budget/OOM/infeasible | `#D55E00` | `X` | dotted |

`min-cut proxy` 只能出现在工程附录或历史审计图，使用空心 `^` 并在图例中写全
`min-cut proxy`；不得使用 AOT min-cut 的实心编码。模型维度使用 panel 或小倍数图，
不再占用颜色通道。

### 2.2 版式与导出

- 单栏宽 `3.3 in`，双栏宽 `7.0 in`；高度由 panel 数确定，避免无效留白。
- 最终排版文字不小于 `7 pt`，轴标题和 panel 标签建议 `8 pt`；不依赖页面缩放才能
  读取。
- 每张图同时导出矢量 `PDF` 和 `SVG`，再导出 `300--600 DPI PNG`。PDF 必须嵌入
  字体；SVG 文本不得被意外转为无法搜索的路径。
- 主数据图必须通过灰度预览和色觉异常预览；结论不得仅由红/绿色差表达。
- 禁止彩虹色板、3D 图、双 y 轴、截断的柱状图基线、面积代表一维量和无样本量的
  平滑曲线。
- 图题不写“PeakAware 更好”；caption 先说比较对象和口径，再回答一个可被图中
  数据证伪的问题。

## 3. 正文图 F-1--F-10

### F-1 PeakAware 系统闭环

- **目的**：回答 C-3 的计划是否从 joint capture 经诊断、repair 和 Top-K 实测，最终
  变为实际 FW/BW executable。
- **输入**：方法契约与稳定代码入口，不读效果数字；节点标注 joint graph、storage-aware
  IR、seeds、D0--D5、repair、Pareto Top-K、lowering、correctness 和 complete-step measurement。
- **编码**：白底流程图；蓝色表示静态分析，橙色表示编译/实测，绿色表示已验收的
  executable；反馈箭头只从 measurement/diagnosis 回到 repair/search。
- **统计**：无；这是架构图，不使用个案数字暗示效果。
- **反误导**：optimizer 明确画在 joint graph 外但在 complete step 内；标注私有 AOT ABI 边界；
  不把 cache/ProfileDB 画成独立创新点。
- **caption 必须回答**：“PeakAware 在哪一步把 saved-memory 规划转化为完整 step 的
  physical-peak 验收？”

### F-2 归一化峰值--吞吐 Pareto 前沿

- **目的**：主回答 RQ-4/C-4，比较相同实测峰值下的有效吞吐。
- **输入字段**：`config_fingerprint`、`strategy`、`measured_peak_bytes`、
  `samples_per_second` 或 `tokens_per_second`、`status`、`correctness_passed`、
  `compiler_mode`、`independent_run_id`。峰值和吞吐分别归一化到同一 workload、同一 compiler mode
  的 matched all-save；Inductor 点不得使用 eager all-save 归一化。
- **编码**：x 轴为 normalized allocated peak，y 轴为 normalized throughput；每模型一个 panel；
  展示每个实测点及非支配前沿，不用拟合曲线。
- **统计**：点为独立进程 median，误差条为 P10--P90；跨模型汇总只在附表报 matched
  speedup 几何平均和 bootstrap 95% CI。
- **反误导**：OOM、timeout 和 correctness failure 不删除，用边缘标记或独立计数；不直接
  汇总不同模型的 samples/s；不用未覆盖全部 workload 的 SAC 点推断全局。
- **caption 必须回答**：“在严格相同的 measured-peak 约束下，哪些配置中 PeakAware 处于
  非支配前沿，哪些配置中不是？”

### F-3 紧预算可行性曲线

- **目的**：回答 RQ-3，检验物理预算满足率及 fixed frontier 导致的不可行区域。
- **输入字段**：`all_save_measured_peak_bytes`、`budget_ratio`、`budget_bytes`、
  `measured_peak_bytes`、`status`、`feasibility_status`、`fixed_frontier_bytes`、`strategy`。
- **编码**：x 轴固定为 all-save 实测峰值的 `50/65/80/95/100%`，y 轴为工作负载级
  预算满足率；策略用固定颜色/marker；不可行点用 `X` 叠加。
- **统计**：对每个 `workload x backend x budget x strategy`，五个独立进程中只有
  `status=ok`、correctness 通过且每进程最大峰值均不超过预算，才判为 workload-cell 满足；
  `budget_violation/OOM/timeout/correctness_failure` 均判为不满足，`unsupported` 与
  `infra_failure` 分列且不伪造为满足。曲线报告满足 cell 的分子/预注册分母及 workload-clustered
  bootstrap 95% CI，不能把五个进程当作五个 workload。
- **反误导**：不将“预测可行”当作“实测满足”；不将 fixed frontier 已超预算的点算作
  搜索失败；不用旧 `4/8 GiB` 宽松预算替代相对预算。
- **caption 必须回答**：“预算逐步收紧时，各方法有多少 workload 真正满足 complete-step
  allocated peak，失败中有多少是 activation-only 方法不可解？”

### F-4 配对 baseline 比较森林图

- **目的**：展开 RQ-3/RQ-4 的逐 workload 差异，防止均值遮蔽负结果。
- **输入字段**：与 baseline matched 的 `config_fingerprint`、`strategy`、
  `measured_peak_bytes`、`steady_state_step_time`、`throughput`、`independent_run_id`、
  `status`。
- **编码**：每行一个 workload-baseline pair；主面板画 log speedup 及 95% CI，辅面板画 peak ratio；
  `1.0` 为明确无效线，行顺序按模型和预算预注册。
- **统计**：在独立进程 repeats 上做 paired bootstrap；表头给出 strict/weak Pareto 胜平负数。
- **反误导**：只有两策略在同一 config 下都有效时才计算 ratio；未匹配点单独列出，不
  默认填 `1`；真实 AOT min-cut 与 proxy 不得合并。
- **caption 必须回答**：“结论是否由少数 workload 驱动，PeakAware 在哪些架构或预算上
  失去优势？”

### F-5 预测峰值与实测峰值 parity

- **目的**：回答 RQ-2，分离纯静态能力与 all-save-assisted calibration 能力。
- **输入字段**：`raw_estimated_peak_bytes`、`calibrated_estimated_peak_bytes`、
  `measured_peak_bytes`、`measured_peak_phase`、`predicted_peak_phase`、`strategy`、
  `config_fingerprint`。
- **编码**： raw 和 calibrated 两个等尺度 panel；x/y 轴单位相同，画 `y=x` 和 +/-10% 参考
  带；低估/高估用不同 marker fill，不用趋势线代替散点。
- **统计**：分别报 signed error mean/P50、APE mean/P50/P90/max、within-10% rate 和 phase
  accuracy；以 workload 为 bootstrap 单元给 95% CI。
- **反误导**：误差分母是 measured peak；calibrated panel 必须注明所需 all-save measurement 及成本；
  不用 phase propagation 结果声称纯静态 phase prediction。
- **caption 必须回答**：“不读取当前 workload runtime baseline 时模型有多准，一次 all-save 校正
  改变了什么、付出了什么？”

### F-6 D0--D5 误差分解瀑布

- **目的**：回答 RQ-1/C-1/C-2，显示从 logical saved 到 runtime peak 时哪一层改变了收益。
- **输入字段**：每个 workload/plan 的 `D0_peak_bytes`--`D5_peak_bytes`、
  `strategy_expected_saved_gain`、`normalized_saved_gain`、`after_fw_gain`、
  `overall_peak_gain`、`diagnostic_primary_cause`。
- **编码**：主图用工作负载级 median 的分步瀑布，各步用中性深浅与正/负纹理；个案图只
  作动机示例，不替代分布。
- **统计**：同时提供各 level 的 P10/P50/P90 和增量符号占比；真实模型根因只报 cause
  frequency/confidence，不报无 ground truth 的 accuracy。
- **反误导**：D0--D3 标为 static，D4 标为 compiler correction，D5 标为 measurement；
  瀑布增量必须能从原始层值重算，不人工调整闭合。
- **caption 必须回答**：“storage alias、recompute liveness、fixed frontier 和 compiler/runtime 中，
  哪些因素在哪些 workload 主导 saved-to-peak 差距？”

### F-7 FW/BW/optimizer 分阶段峰值

- **目的**：回答 RQ-1 中的 peak migration，并检查 optimizer/fixed frontier 是否遮蔽 activation saving。
- **输入字段**：`fw_peak_bytes`、`bw_peak_bytes`、`optimizer_peak_bytes`、
  `measured_peak_bytes`、`measured_peak_phase`、`strategy`、`config_fingerprint`。
- **编码**：按 workload 分 panel 的 grouped point-range 或 grouped bar；阶段用固定顺序 FW/BW/OPT，策略用
  颜色/marker；总峰值用细水平线。
- **统计**：点/柱为独立运行 median，区间为 P10--P90；附注报告 dominant phase 切换的配对比例。
- **反误导**：柱状图 y 轴从零开始；阶段峰值不得相加为 overall peak；optimizer 即使为 eager
  也必须留在图中。
- **caption 必须回答**：“SAVE 计划改变后物理峰值迁移到了哪个 phase，为什么 after-FW
  降低未必降低 complete-step peak？”

### F-8 Top-K 后悔与排名 ECDF

- **目的**：回答 RQ-5/C-5，验证静态排名需要多少实测候选才能接近实测最优。
- **输入字段**：固定 candidate pool 的 `candidate_id`、`estimated_rank`、`measured_rank`、
  `estimated_peak_bytes`、`measured_peak_bytes`、`measured_step_time`、`top_k`、`status`。
- **编码**：一个 panel 画 rank correlation/true-best recall@K，一个 panel 画各 K 的 normalized regret ECDF；K 用
  线型+marker，不用渐变色。
- **统计**：每 workload 先计算 regret，再画 ECDF；报 Spearman/Kendall、recall@K、P50/P90 regret 及
  bootstrap 95% CI。无有效候选的 workload 单独计数。
- **反误导**：不在测得的全集上再选 candidate pool；Top-K 必须包含多样性规则所保留的点；
  不将弱排名相关性隐藏在最终 best-of-K 结果后。
- **caption 必须回答**：“静态 cost/peak 排名在多大 K 下才稳定找到近似最优 executable，
  未实测更多候选的代价是什么？”

### F-9 优化、编译与 cache 摊销

- **目的**：回答 RQ-5/C-5，说明 PeakAware 一次性成本需要多少训练 step 摊销。
- **输入字段**：`optimization_capture_us`、`optimization_ir_build_us`、
  `optimization_analysis_us`、`optimization_executor_build_us`、
  `optimization_candidate_validation_measurement_us`、`compile_time_us`、`cache_hit_rate`、
  `cold_or_warm`、`baseline_step_time`、`selected_step_time`。
- **编码**：上 panel 为 cold/warm 分阶段堆叠时间，下 panel 为累计时间差随训练 steps 的
  break-even 曲线；堆叠部分用可区分纹理。
- **统计**：各阶段报 median/P90；amortization steps 仅在稳态每 step 有正收益时计算，否则写
  `not amortized`。
- **反误导**：cold 与 warm cache 不得混合；不把 profiling/measurement 时间隐藏到“编译”之外；
  cache hit 必须同时验证 key 与 plan identity，不只报比率。
- **caption 必须回答**：“一次完整优化的成本由什么组成，cache 复用后在多少 step 之后取得
  净收益，哪些点永远无法摊销？”

### F-10 系统组件消融

- **目的**：检验 C-2/C-4/C-5 中每个组件是否对最终物理预算或吞吐有可测贡献。
- **输入字段**：预注册 variants（full、without storage normalization、without phase/fixed model、
  without diagnosis hints/repair、without calibration、`K=1`、without cache）的 budget success、
  throughput、prediction error、search/compile cost 和 candidate count。
- **编码**：指标分成独立小 panel 的 paired delta dot plot；横轴为相对 full 的变化，零线显式可见；
  消融项使用固定 marker，不使用“红差绿好”作唯一编码。
- **统计**：以 workload 配对差为样本，报 median/P10/P90 和 bootstrap 95% CI；多重比较时
  同时报 effect size，不仅报 p-value。
- **反误导**：每次只改一个因素；共享同一候选 frontier 和实测协议；“hints neutral”也必须
  保留；不用 synthetic-only 收益替代真实 workload 结果。
- **caption 必须回答**：“哪些组件对预算满足、排名或摊销必要，哪些在当前搜索面上
  没有产生可测改善？”

## 5. 输出目录与机器可读契约

每个图表输出一个独立目录，建议形式如下：

```text
publication/figures/F2_pareto/
  figure.pdf
  figure.svg
  figure.png
  source.csv
  source.schema.json
  plot_config.json
  caption.md
  provenance.json
  render.log
```

`source.csv` 仅是冻结 raw/processed data 的图级投影，不是新的事实源。`provenance.json`
至少包含 `figure_id`、`ev_ids`、`source_checksums`、`generator_commit`、`environment_lock_checksum`、
`command`、`generated_at_utc` 和 `status=frozen`。表格同时导出 Markdown、CSV 和 LaTeX，三者必须
来自同一数据帧。

## 6. 图表冻结验收

每个 `F-*`/`T-*` 只有在以下检查全部通过后才可进入正文：

- 输入只引用 evidence ledger 中 `frozen` 的 `EV-*`，checksum 与 manifest 一致；
- 去重后 workload `N`、失败数和 baseline coverage 与 T-3/T-7 一致；
- 从 raw artifact 重算一个抽样点，与 plotted source 一致；
- 轴单位、allocated/reserved、raw/calibrated、proxy/real baseline 无混用；
- PDF/SVG/PNG 全部生成，字体、裁切、图例、7--8 pt 最小字号符合要求；
- 通过彩色、灰度和常见色觉异常预览，marker/线型在黑白下仍可区分；
- caption 明确回答本文档为该图规定的问题，且数字均能回溯到 `EV-*`；
- 两名复核者中至少一名不参与该图脚本实现，并记录数据口径和视觉反误导检查。
