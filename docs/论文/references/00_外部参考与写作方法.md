# 外部参考与写作方法

## 1. 使用原则

本文档是“来源证据卡”，不是 Related Work 正文，也不改写 `C-*`、`RQ-*` 或实验设计。每个来源都回答三个
问题：它支持什么，它不能支持什么，它在论文何处使用。引用时应回到论文、官方文档、源码或官方指南的原始
页面，不把搜索结果、二手博客或外层仓库图表当作证据。

一个来源能说明“现有方法的目标和边界”，不等于它证明“PeakAware 在实验上更好”。C-1--C-5 的效果结论必须
来自冻结 `EV-*`，不能由外部文献代替。

## 2. Rematerialization 研究来源

### 2.1 Checkmate

- 原始来源：[Checkmate: Breaking the Memory Wall with Optimal Tensor Rematerialization](https://arxiv.org/abs/1910.02653)
- 支持什么：将 tensor rematerialization 形式化为 memory--time 优化问题，结合算子 profile、MILP/近似解和执行系统。
  它为“先定义目标与约束，再介绍求解与执行”的叙事顺序提供范例。
- 不能支持什么：不能证明 PeakAware 首次提出自动 checkpoint、SAVE/RECOMPUTE 优化或 memory--time tradeoff；
  也不能证明 PeakAware 的峰值模型或搜索结果正确。
- 论文落点：背景章定义 rematerialization；Related Work 比较广义调度目标与 PeakAware 的 compiled-PyTorch
  complete-step physical peak 约束；问题定义章主动承认先验工作。

### 2.2 Dynamic Tensor Rematerialization

- 原始来源：[Dynamic Tensor Rematerialization](https://arxiv.org/abs/2006.09616)
- 支持什么：DTR 通过挑战“rematerialization 必须离线静态规划”的默认前提，展示在线贪心策略、理论分析
  和 PyTorch 原型如何共同支撑一个可证伪故事。
- 不能支持什么：不能用 DTR 结果推断 saved activation 与 complete-step physical peak 在 PeakAware 实验中必然错位，
  也不能证明 PeakAware 的静态搜索优于在线策略。
- 论文落点：Related Work 的在线/离线调度分类；引言写作参照其“挑战默认代理目标”模式，但不转移实验结论。

### 2.3 Rockmate

- 原始来源：[Rockmate: an Efficient, Fast, Automatic and Generic Tool for Re-materialization in PyTorch](https://arxiv.org/abs/2307.01236)
- 支持什么：利用真实模型的 block/sequence 结构，组合通用但昂贵的细粒度解与快速但结构化的解；这是从
  两种方法的张力推导混合系统的优秀范例。
- 不能支持什么：不能把 PeakAware 的 min-cut seed + diagnosis/repair + Top-K 直接称为 Rockmate 式最优解，也不能
  代替搜索开销、排序质量和最终 Pareto 的本项目测量。
- 论文落点：Related Work 的层次化 solver 比较；系统设计章用“快速 seed 与少量实测校正的互补”解释
  C-5，同时明确 PeakAware 不是 Rockmate 算法的复制。

## 3. PyTorch 目标语义与实现来源

### 3.1 PyTorch Activation Checkpointing 官方博客

- 原始来源：[Current and New Activation Checkpointing Techniques in PyTorch](https://pytorch.org/blog/activation-checkpointing-techniques/)
- 支持什么：官方解释 activation checkpointing、Selective Activation Checkpointing、min-cut partitioner 和 Memory Budget API
  的 speed--memory 权衡；其图中 memory 指定区域为 saved-for-backward memory，为“saved-memory 目标不等于完整
  physical peak”的语义区分提供官方背景。
- 不能支持什么：不能从概念图推断 PyTorch min-cut 在 PeakAware 的任意 workload 上会违反 physical budget，也不能
  证明当前仓库的 `min_cut_proxy` 是真实 PyTorch min-cut baseline。
- 论文落点：背景章解释 AC/SAC/min-cut/memory-budget 语义；引言精确限定 C-1 的目标错位；实验章
  只用冻结的真实 baseline 回答 RQ-3。

### 3.2 AOTAutograd min-cut 设计说明

- 原始来源：[Min-cut optimal recomputation with AOTAutograd](https://dev-discuss.pytorch.org/t/min-cut-optimal-recomputation-i-e-activation-checkpointing-with-aotautograd/467)
- 支持什么：说明 AOTAutograd 如何在 joint graph 上将 forward/backward partition 规约为 min-cut，其“optimal”依赖
  允许重算集、简化成本和 fusion 等前提，并明确讨论 graph 内部 memory usage 不在该 cut 目标中。
- 不能支持什么：不能因为它忽略 graph-internal memory 就宣称 min-cut “错误”或“必然更差”；它也不支持
  PeakAware 的 greedy/repair 是 global optimum。
- 论文落点：问题定义中精确对比 boundary cut objective 与 complete-step peak constraint；Related Work
  承认 min-cut 有效完成其既定目标，避免写成对现有方法的泛化否定。

### 3.3 AOTAutograd 官方文档

- 原始来源：[AOT Autograd: How to use and optimize](https://docs.pytorch.org/functorch/stable/notebooks/aot_autograd_optimizations.html)
- 支持什么：AOTAutograd 预先获得 forward/backward graph，为 partitioner、重算与 compiler 优化提供基础设施；
  fusion-aware recomputation 可能同时改善 memory 和 runtime，因此不应把“重算必然减速”当作前提。
- 不能支持什么：AOT joint capture 本身不是 PeakAware 独有创新；文档也不保证私有 ABI 跨 PyTorch 版本稳定，
  更不能代替 C-3 的 plan identity、lowered executable 和 correctness 证据。
- 论文落点：背景章介绍 joint graph/partitioner；实现章说明 PeakAware 对现有基础设施的使用及私有 ABI 风险。

### 3.4 PyTorch partitioner 源码

- 原始来源：[torch/_functorch/partitioners.py](https://github.com/pytorch/pytorch/blob/main/torch/_functorch/partitioners.py)
- 支持什么：源码是检查当前 `choose_saved_values_set`、saved-value size、memory ratio、recomputation ban、
  knapsack/min-cut 和 FW/BW 提取顺序的直接实现依据；可用于解释真实 baseline 接入时的 provenance。
- 不能支持什么：`main` 分支是流动目标，不能用未锁定的当前页代表实验环境 `2.13.0+cu130` 的确切实现；
  实现中未使用 physical peak 也不自动证明 PeakAware 的模型完备。
- 论文落点：背景/实现章解释实际 partitioner；Artifact 中应额外保存与冻结 torch wheel/commit 对应的 permalink
  或源码摘要哈希，避免引用漂移。

### 3.5 PyTorch issue #149258

- 原始来源：[PyTorch issue #149258](https://github.com/pytorch/pytorch/issues/149258)
- 支持什么：提供 residual-chain 的具体 reproducer，展示不同 SAVE 集合可在类似保存量下带来不必要的
  连续重算，支持“cut-level proxy 与执行行为可能错位”作为研究动机。
- 不能支持什么：单个 issue/reproducer 不能证明 complete-step physical peak 错位具有普遍性，不能代替多模型、
  多预算与真实 min-cut baseline 实验，也不能把 issue 中的“suboptimal”直接外推为 PeakAware 更优。
- 论文落点：引言或 motivation 章的外部实例，紧接本项目的可控反例和真实模型证据；不把它当作主结果。

## 4. 论文写作与评审方法

### 4.1 Simon Peyton Jones：一个可记住的思想

- 原始来源：[How to Write a Great Research Paper](https://simon.peytonjones.org/great-research-paper/) 与
  [讲义 PDF](https://www.microsoft.com/en-us/research/uploads/prod/2016/07/How-to-write-a-great-research-paper.pdf)
- 支持什么：论文应围绕一个鲜明、可复用的 idea，按 problem、importance、unsolved gap、idea、evidence、comparison
  建立叙事；贡献要具体、可证伪，引言的每个 claim 应能指向证据。
- 不能支持什么：写作建议不是科学证据，不能用好故事弥补缺失的 baseline、效果矩阵或反例讨论。
- 论文落点：用于审查标题、摘要、引言和贡献列表。PeakAware 的“one ping”固定为：优化 saved activations
  不足以约束 end-to-end training physical peak。

### 4.2 USENIX 系统论文写作

- 原始来源：[How (and How Not) to Write a Good Systems Paper](https://www.usenix.org/conferences/author-resources/how-and-how-not-write-good-systems-paper)
- 支持什么：系统论文需要有重要问题、新思想、真实实现和能支持声明的证据；常见失败包括问题不重要、
  系统未落实、论据不足和表达混乱。
- 不能支持什么：评审经验不是会议录用保证，也不能指定 PeakAware 必须得到某一方向的实验结果。
- 论文落点：用于章节审查：每个系统组件必须对应 failure mode 和 ablation；每个效果声明必须对应实测；
  系统不得停在静态报告而缺少可执行计划。

### 4.3 Heilmeier Catechism

- 原始来源：[DARPA Heilmeier Catechism](https://www.darpa.mil/about/heilmeier-catechism)
- 支持什么：用非术语化问题检查目标、现状、新意、可行性、风险、成本和成功标准，适合在动笔前检验
  一个项目是否只是功能列表。
- 不能支持什么：八问只是规划和沟通框架，不证明方法新颖，不替代 Related Work 检索、实验和统计。
- 论文落点：与 `01_论点与故事线.md` 的八问表对照，用于开题、中期检查、摘要和答辩前的非术语化压力测试。

## 5. 经验评估与 Artifact 来源

### 5.1 ACM Artifact Review and Badging

- 原始来源：[ACM Artifact Review and Badging](https://www.acm.org/publications/policies/artifact-review-and-badging-current)
- 支持什么：区分 Artifacts Available、Artifacts Evaluated -- Functional/Reusable 以及 Results Reproduced/Replicated，
  为代码、数据、文档、持久可用性和独立验证提供标准词汇。
- 不能支持什么：自评对齐不等于已获得 ACM badge；在未经正式评审前不得在论文或仓库展示该 badge。
- 论文落点：Artifact Appendix 和发布检查表；指导复现包区分“可用”、“可运行”、“可复用”和“结果被独立重现”。

### 5.2 Systems Artifact Evaluation

- 原始来源：[Systems Artifact Evaluation](https://sysartifacts.github.io/)
- 支持什么：汇总 systems 会议 Artifact Evaluation 资源，强调可操作的 README、环境、运行时间、测试步骤、
  预期结果和评审者成本，支持设计 smoke/full 两级路径。
- 不能支持什么：它是资源入口，不替代投稿会议当年的具体 AE 规则；也不保证一个能运行的 Artifact 就有正确的实验设计。
- 论文落点：Artifact 打包与评审指南；使用该站点定位目标会议的最新模板，但在提交时锁定确切规则版本。

### 5.3 SIGPLAN Empirical Evaluation Guidelines

- 原始来源：[SIGPLAN Empirical Evaluation Guidelines](https://www.sigplan.org/Resources/EmpiricalEvaluation/)
- 支持什么：强调研究问题、实验设计、工作负载选择、统计、可复现性、局限性和声明之间的对齐；
  为报告原始样本、不确定性、失败点与内外部效度威胁提供方法论。
- 不能支持什么：指南不会替 PeakAware 选择唯一正确的 repeat 数、CI 方法或 workload，具体协议必须结合
  GPU 系统的波动、成本和 RQ 预先冻结。
- 论文落点：Evaluation 开头的方法声明、Threats to Validity 和 Artifact Appendix；审查 paired conditions、
  workload-level 统计单位、原始样本保留和失败不静默删除。

### 5.4 MLSys Call for Papers

- 原始来源：[MLSys 2025 Call for Papers](https://mlsys.org/Conferences/2025/CallForPapers)
- 支持什么：官方 CFP 将 machine learning systems 的设计、实现、分析和经验研究置于同一范围，可用于
  检查 PeakAware 是否同时回答系统问题、提供可执行实现并进行足够评估。
- 不能支持什么：CFP 不是学术相关工作，不应在 Related Work 中用它证明创新性；2025 页面也不代表未来年份
  的投稿格式、页数或 Artifact 规则。
- 论文落点：只用于选题定位、投稿清单和内部审稿标准；正式投稿前重新查询目标年份 CFP，不将这一页写入核心技术参考。

## 6. PeakAware 叙事的可执行组合

外部叙事模式只用来帮助组织本项目已有证据，不借来它们的创新性或结果。推荐组合是：

1. 用 DTR 的“默认假设反转”引出 saved-memory proxy 不总能代表 complete-step physical peak；
2. 用 Checkmate 的问题形式化方式定义给定 joint graph、硬件/编译配置、optimizer 和物理预算下的 SAVE 选择；
3. 用 PyTorch 官方资料精确说明 min-cut 已经有效优化其 boundary objective，然后限定 PeakAware 补足的执行时间线范围；
4. 用 Rockmate 的“互补优点”说明为什么保留快速 seed，再以 peak diagnosis/repair 和 Top-K compilation calibration 闭环；
5. 用 Simon Peyton Jones 和 USENIX 方法审查每个贡献是否可证伪、每个组件是否由 failure mode 推导、每个 claim 是否有 `EV-*`；
6. 用 SIGPLAN/ACM/SYS Artifact 指南审查证据是否完整、可复现、包含失败并明示限制。

叙事不得按研发时间顺序写成“先实现 IR，后来又加了 diagnostics 和 cache”。最短路径是：物理预算问题 -> 代理目标错位
-> 一般原因 -> 解释/修复/下发/实测闭环 -> 证据与边界。

## 7. 引用和写作自查

- [ ] Related Work 不把 Checkmate、DTR、Rockmate 写成简单的“旧方法更差”，而是对比目标、执行模型和范围；
- [ ] 对 PyTorch min-cut 的描述同时引用官方设计说明与冻结版本源码，不用当前 proxy 冒充官方实现；
- [ ] 源码链接使用对应 torch commit/tag 的 permalink，正文不仅引用漂移的 `main`；
- [ ] issue #149258 只是动机与反例线索，不充当普遍效果证据；
- [ ] 摘要和引言只有一条主线，贡献 bullet 分别指向 C-1--C-5 中的具体论点和冻结 `EV-*`；
- [ ] 不使用“首次 automatic rematerialization”、“globally optimal”、“全面优于 SAC/min-cut”等无法由来源或实验支持的表述；
- [ ] 每个数字结论来自 evidence ledger 的 `frozen` 产物，不从外部论文、仓库旧 artifact 或写作指南借数字；
- [ ] 投稿前核对所有 URL、访问日期、BibTeX、作者、年份和版本，并重新阅读目标年份 CFP/Artifact 规则。
