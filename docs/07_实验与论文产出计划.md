# PeakAware 实验与论文产出计划

## 1. 研究问题

- RQ1：saved-memory budget 与端到端训练物理峰值存在多大偏差？
- RQ2：Storage-Aware 模型能否准确预测不同 SAVE 方案的 FW/BW/overall peak？
- RQ3：Peak-aware repair 能否比 PyTorch min-cut 更稳定地满足物理预算？
- RQ4：相同实测峰值下，PeakAware 能否提高有效吞吐？
- RQ5：Costmodel、Profiling 和 Top-K 校正分别改善多少候选排序质量？
- RQ6：Fixed Frontier Analyzer 能否提前识别无效重计算或不可行预算？
- RQ7：系统能否解释 min-cut 的预计 saved gain 为什么没有转化为 overall peak gain？
- RQ8：诊断生成的 repair hints 是否改善搜索效率和最终计划？
- RQ9：搜索、profiling 和编译成本需要多少 step 摊销？

## 2. 模型

### 解释性模型

- activation-dominated residual chain；
- Tiny MLP；
- Tiny attention/Transformer block。

解释性模型用于因果和最优性验证，不替代真实模型结果。

### 主模型

| 模型 | 任务 | 价值 |
|---|---|---|
| ResNet-50 | 图像分类 | residual/CNN/workspace |
| ViT-B/16 | 图像分类 | attention/MLP/residual |
| BERT-Base | MLM 或分类 | encoder/dynamic mask |
| GPT-2 | causal LM | decoder/LM-head/fixed frontier |

GPT-2 XL 根据硬件作为主规格或扩展规格。

### 扩展模型

- Swin-T：固定 224x224；
- LLaMA-7B/8B：FakeTensor 全图分析，缩小模型真实验证；
- Mixtral-style Small MoE：固定 capacity 或 routing trace。

## 3. Baselines

1. Eager/compile default，无重计算。
2. 手工 block checkpoint。
3. PyTorch Selective Activation Checkpoint。
4. AOTAutograd min-cut rematerialization。
5. PyTorch memory budget 多个预算点。
6. Greedy `bytes/recompute_cost`。
7. Region-only checkpoint planner。
8. PeakAware full。

相关工作比较：对 Checkmate/Rockmate 风格方法至少提供小图 exact/近似算法对照、公开实现对照
或明确的模型与目标差异，不能只比较 PyTorch 默认方案。

## 4. 自变量

- 物理预算：绝对 GiB 和 baseline peak 的相对比例；
- batch/microbatch；
- image size 或 sequence length；
- BF16/FP32，必要时 AMP；
- SGD、AdamW、fused AdamW；
- aot_eager 与 Inductor；
- cost source；
- safety margin；
- Top-K；
- search iteration 和 candidate 粒度。

## 5. 主要指标

### 预算与性能

- `measured_peak_allocated_bytes`；
- `measured_peak_reserved_bytes`；
- budget violation rate；
- step time；
- samples/s 或 tokens/s；
- 相同实测峰值下 speedup；
- 最大可行 microbatch。

### 算力解释

- MFU 和 HFU，明确 FLOPs 口径；
- SM Active；
- Tensor Core utilization；
- DRAM throughput；
- recompute FLOPs 和 useful model FLOPs。

不能使用单一 `nvidia-smi GPU-Util` 作为“充分利用算力”的证据。

### 模型准确度

- peak prediction MRE/P50/P90/max；
- peak phase classification accuracy；
- cost prediction MRE；
- candidate ranking Spearman/Kendall；
- OOM/feasible classification accuracy。

### 根因诊断

- policy estimation gap、realization gap 和 total expectation gap；
- synthetic ground-truth root-cause precision/recall；
- primary/secondary cause confidence calibration；
- D0--D5 counterfactual delta；
- diagnosis-driven repair 命中率；
- 使用 hints 前后的搜索迭代数和最终吞吐。

### 优化开销

- capture、IR、search、profiling、compile 时间；
- CPU 主存和磁盘；
- candidate/repair/Top-K 数量；
- amortization steps；
- capture/analysis/executable cache hit rate，以及 executable 层 plan/artifact 分键复用率。

## 6. 核心实验

### E1：目标错位

对不同 min-cut memory budget 测量：

```text
after-FW retained
BW recompute transient
gradient/fixed frontier
overall physical peak
```

证明 saved activation 降低不保证 overall peak 单调降低，并区分 residual wave 与 fixed
frontier 两种机制。

执行模式边界必须单独说明：反向峰值反升不是“重计算必然导致”的现象，而是当 saved-activation
目标与真实 backward liveness 脱节时出现的现象。在 PyTorch 中，最典型、最明显的案例发生在
AOTAutograd/min-cut 图执行路径；eager 原生训练没有 min-cut，因此不会出现同一种
cut-induced rematerialization wave。但 eager checkpoint 若边界不佳，也可能出现 overall peak
不降，或收益被 backward transient、gradient frontier、loss frontier 抵消。实验报告必须把
`eager checkpoint`、`aot_eager min-cut` 和 `Inductor memory budget` 分开归因。

### E2：峰值模型

逐层加入：

```text
logical value bytes
-> storage alias
-> phase liveness
-> gradients/optimizer
-> allocator rounding
-> workspace/compiler correction
```

报告每层带来的误差变化。

### E3：预算满足率

在多个绝对预算下比较所有 baseline 的：可行率、OOM、超预算比例和 fallback 次数。

### E4：相同峰值下吞吐

绘制 x=实测峰值、y=step time/throughput 的 Pareto 图。论文主结论以实测峰值分桶，不以
saved bytes 分桶。

### E5：Cost 来源

比较：

```text
FLOPs fallback
Legacy Costmodel
ProfileDB
Costmodel + profile residual
+ Top-K end-to-end correction
```

关注最终 plan ranking 和吞吐，而不只看单算子误差。

### E6：Fixed Frontier

改变 optimizer、fused mode、batch 和 sequence，验证 Analyzer 是否能判断：

- 可优化；
- 低 activation headroom；
- activation-only 不可行；
- 继续降低 saved activation 无收益。

### E7：Microbatch 增强

若实现外层搜索，比较固定 microbatch 与 `microbatch + SAVE` 联合枚举，验证显存释放是否转化
为更高有效吞吐，而非更高无效 HFU。

### E8：Min-Cut 根因诊断

在可控图中分别触发 alias pinning、rematerialization wave、shared recompute expansion、fixed
frontier、peak phase migration、workspace growth 和 cost misrank，验证 root-cause label、证据
与 repair hint。真实模型报告 expected saved gain、actual overall peak gain 和 D0--D5 waterfall。

比较关闭/启用诊断 hints 的 PeakAware，确认诊断不仅生成解释，还能减少无效 repair、提前终止
fixed-frontier 搜索或改善最终计划。

## 7. 消融

1. 去掉 alias/storage；
2. 只优化 saved bytes；
3. 去掉 peak-aware repair；
4. 去掉 root-cause diagnosis，仅保留 peak 数字；
5. 去掉 diagnosis-driven hints；
6. 去掉 Fixed Frontier；
7. FLOPs vs Costmodel vs ProfileDB；
8. 无 Top-K 校正；
9. value vs region vs 分层候选；
10. 不同 safety margin；
11. 不同 compile Top-K；
12. 禁用单个插件，验证插件层贡献。

## 8. 正确性协议

- 相同 seed、输入、初始化；
- forward output/loss 对比；
- 每个 parameter gradient 的绝对和相对误差；
- 多 step 参数差异；
- dropout/RNG；
- AMP/GradScaler；
- tied/shared weights；
- compile/eager 双路径。

正确性失败的候选不能进入性能结果。

## 9. 测量协议

- 不同方案使用独立进程；
- 固定 GPU、功耗模式、软件版本；
- 充分 warmup；
- CUDA Event 计时并同步；
- 至少 20--50 个稳定 step；
- 报告 median、IQR/P10/P90；
- allocated 和 reserved 同时报告；
- 编译时间与稳态 step time 分开；
- 保存原始 JSON/CSV、配置和环境 fingerprint。

## 10. 论文贡献表述

建议贡献：

1. 系统刻画 PyTorch saved-memory min-cut 与端到端训练峰值之间的错位及若干根因，重点分析
   rematerialization wave 与 fixed backward frontier。
2. 设计 D0--D5 反事实诊断，解释预计 saved gain 未转化为 overall peak gain 的根因。
3. 设计一次 joint graph 上的 storage/phase/compiler-aware peak model 和 fixed-frontier 分析。
4. 提出 min-cut seed + diagnosis/peak-live-set repair 的可扩展 SAVE 优化，并生成可执行 AOT
   plan。
5. 构建插件化 Costmodel/ProfileDB/Top-K 校准系统，在多类模型上验证预算满足率和吞吐。

禁止表述：首次自动 checkpoint、首次时间内存权衡、首次发现 residual cut 问题。
避免表述：eager 原生重计算一定不会反升，或所有重计算都会导致反向峰值反升。论文应限定为：
cut-induced rematerialization wave 主要来自 AOTAutograd/min-cut 图分区与调度；eager checkpoint
的潜在问题应表述为边界选择不佳或 fixed/transient frontier 抵消收益。

## 12. 里程碑

### G0：机会验证

真实模型上的 min-cut/AC 对照、fixed frontier 和 Inductor 后现象。

### M0：可运行闭环

fake joint capture、storage/legality、fixed frontier、手工 SAVE closure/liveness、自定义 partition、
aot_eager 正确性，以及 compiled FW/BW + eager optimizer 的完整 step peak/time。

### M1：PeakAware 搜索

Legacy adapter、storage-aware candidate、greedy/min-cut seeds、repair、wave/risk/early-stop 和 Top-K。

### M2：研究工程化

ProfileDB、D0--D3 静态诊断、隔离 worker、D4 compiler/D5 runtime 校正、三层 cache、插件替换点、
主模型实验和可复现报告。D4/D5 不得早于可执行 partition/runtime 闭环实现。

### M3：扩展

dynamic shape、microbatch、MoE、exact solver 和其他独立研究方向。

## 13. 最终验收

只有满足以下条件才能宣称完整 PeakAware：

1. 搜索只捕获一次同一 graph key 的 joint graph；
2. 最终计划由 SAVE 集合唯一标识并可下发；
3. 峰值模型包含 fixed state、BW transient 和 storage alias；
4. 每个 min-cut/baseline 计划都有期望收益差距、根因证据和修复建议；
5. 诊断 hints 能改善搜索，或正确识别无收益/不可行配置；
6. 多个真实模型上预算满足率和吞吐优于关键基线；
7. Top-K 编译后结果与静态预测误差被公开报告；
8. 所有性能候选通过数值正确性检查；
9. 优化成本可通过 capture/analysis/executable cache 和 ProfileDB 摊销；
10. M2 插件和 patch 在异常后无全局状态泄漏；
11. 完整 step 明确由 compiled FW/BW 与 eager optimizer phase 组成，候选验证不推进用户状态。
