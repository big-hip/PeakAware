# PeakAware 联合重计算实现计划

## 1. 设计原则

1. 只捕获一次原始训练联合图，不为每个候选重新运行 Dynamo/AOT。
2. 核心决策始终是前向值是否 SAVE；RECOMPUTE 闭包和 backward 顺序由决策派生。
3. 搜索约束使用完整训练峰值，不把 saved activation 总和当作物理峰值。
4. FakeTensor 负责大规模元数据分析，真实 GPU 负责 cost 校准、Top-K 验证和最终选择。
5. M0/M1 核心模块通过显式类型和构造函数依赖连接；M2 才为已稳定的替换点加入插件。内部 API
   patch 始终必须作用域化并可恢复。

## 2. 总体架构

```text
TrainingRequest
      |
      v
Fixed-state feasibility check
      |
      v
FakeTensor + AOTAutograd joint capture  -- once
      |
      v
Storage-Aware JointTrainingIR
      |                         \
      |                          -> CostProvider chain
      v
Baseline/min-cut diagnostic + root-cause report
      |
      v
Candidate SAVE values + legality + repair hints
      |
      v
min-cut seeds -> peak simulation -> peak-aware repair -> local improvement
      |
      v
Pareto Top-K plans
      |
      v
AOT partition lowering -> aot_eager dry-run -> Inductor compile
      |
      v
Compiled FW/BW + eager optimizer phase -> runtime validation
      |
      v
Executable plan + optional cache + fallback
```

## 3. 核心 IR

FX node 不是显存分配单位。系统使用四层表示：

```text
OpInfo       算子依赖、阶段、重算合法性和 cost signature
ValueInfo    逻辑 tensor、producer/consumers、FW/BW 边界属性
StorageInfo  物理 storage、alias values、字节和生命期
RegionInfo   block、residual、attention、MLP 等分层搜索单元
```

建议数据结构：

```python
@dataclass(frozen=True)
class ValueInfo:
    id: int
    producer_id: int | None
    consumer_ids: tuple[int, ...]
    storage_id: int | None
    logical_nbytes: int
    phase: str
    crosses_fw_bw: bool
    recomputable: bool
    mandatory_save_reason: str | None

@dataclass(frozen=True)
class StorageInfo:
    id: int
    value_ids: tuple[int, ...]
    physical_nbytes: int
    is_external: bool

@dataclass(frozen=True)
class JointTrainingIR:
    ops: tuple[OpInfo, ...]
    values: tuple[ValueInfo, ...]
    storages: tuple[StorageInfo, ...]
    regions: tuple[RegionInfo, ...]
    graph_key: str
```

搜索阶段不直接修改 `fx.Node`，防止候选之间共享可变状态。

## 4. Legality Pass

以下情况默认强制 SAVE 或设为 barrier：

- 无法函数化的 mutation/in-place；
- 不可恢复 RNG 状态的随机算子；
- I/O、collective、自定义有副作用算子；
- graph break 和 opaque region 的跨边界值；
- 重计算会改变数值语义的值；
- 用户或插件声明的 mandatory value。

Dropout 必须保存并恢复 RNG state，或强制保存对应输出。自定义算子缺失 FakeTensor 支持时，
优先通过 `torch.library.register_fake` 插件注册 meta/fake 实现。

## 5. Fixed Frontier Analyzer

分析分为两层：捕获前使用参数、buffer、梯度总量和 optimizer 公式做粗粒度预检查；joint IR
建成后再根据梯度物化顺序、mandatory values 和 phase timeline 生成精化结果。只有精化结果
进入最终峰值约束，粗粒度结果用于提前拒绝明显不可行的请求。

精化分析估算 activation recomputation 无法消除的下界：

```text
fixed_floor(t) = parameters
               + buffers
               + gradients_live(t)
               + optimizer_states
               + optimizer_temporary(t)
               + mandatory_workspace(t)
```

输出：

```python
@dataclass(frozen=True)
class FeasibilityReport:
    user_budget_bytes: int
    fixed_peak_lower_bound: int
    activation_budget_bytes: int
    dominant_phase: str
    status: str
    explanations: tuple[str, ...]
```

状态包括：

- `FEASIBLE`；
- `LOW_ACTIVATION_HEADROOM`；
- `INFEASIBLE_BY_ACTIVATION_ONLY`；
- `UNKNOWN_WORKSPACE_BOUND`。

该分析器既是工程保护，也是论文中的 fixed backward frontier 贡献。

`ActivationPlanner` 的决策域只包含 activation storage 的 SAVE/DROP；参数、梯度、optimizer
state 和 optimizer temporary 不进入候选集合。它们由 `StepPeakModel` 统一放入 FW/BW/optimizer
phase timeline。`Optim_IR` 第一版只作为 optimizer 语义和内存公式的参考/适配来源，不是 MVP
运行时依赖。

optimizer 不进入 AOT joint graph。最终 `TrainingStepExecutor` 顺序执行 compiled FW/BW 和 eager
`optimizer.step()`；候选验证使用 model/optimizer/RNG 副本，不能推进用户原始训练状态。

## 6. 完整峰值模型

给定 SAVE 方案 `x`：

```text
fixed(t) = parameters + buffers + gradients(t)
         + optimizer_state + optimizer_temp(t)

variable(t, x) = saved_activations(t, x)
               + recomputed_values(t, x)
               + materialized_outputs(t, x)
               + workspace(t, x)

P(x) = max_t allocator_model(fixed(t) + variable(t, x))
```

仿真必须处理：

- view/alias 共享 storage；
- tuple/list 多输出；
- graph output pinning；
- saved value 的最后一个 backward consumer；
- shared recompute ancestor 去重；
- gradient 首次物化和持续存活；
- allocator alignment/rounding；
- compiler fusion 和 workspace 的校正项。

每个结果必须包含峰值解释，而不仅是一个数字：

```text
phase + op_id + live storage set
+ parameter/gradient/optimizer/saved/recomputed/workspace breakdown
```

## 7. SAVE 候选

候选值需要满足：

- 是 forward 产生且 backward 使用的值；
- legality pass 允许重计算；
- 能代表独立 storage，或明确关联到 alias base；
- 字节、生命期或重算代价超过阈值。

优先候选包括 residual boundary、block input/output、attention Q/K/V、attention output、MLP
中间值和长生命周期 storage。

采用分层粒度：

1. 先在 region/block 边界生成粗粒度方案；
2. 根据峰值 live set 展开热点 region；
3. 将 value/region move 规范化为受影响的 `storage_id -> StorageEffect`；
4. 搜索、去重、收益估计和 peak repair 都按 storage effect 执行；
5. 仅在 AOT partition lowering 时，将最终 storage 决策投影为 value id 的 SAVE 集合。

同一 storage 的 view/alias 不能作为多个独立释放收益累计。若某个 alias、graph output 或 mandatory
value 仍 pin 住 base storage，则该 move 的 `released_at_peak_bytes` 必须为零或仅计入实际可释放
部分。value ids 是 partition ABI，不是搜索目标的内存计量单位。

`StorageEffect` 是 plan/move 在特定 timeline 下的派生量，不属于静态 JointTrainingIR：

```python
@dataclass(frozen=True)
class StorageEffect:
    storage_id: int
    decision: str  # SAVE | DROP
    decision_value_ids: tuple[int, ...]
    alias_value_ids: tuple[int, ...]
    released_at_peak_bytes: int
    retained_after_fw_bytes: int
    pinning_value_ids: tuple[int, ...]
    confidence: float
```

closure 和 legality 仍按 value 语义判断；storage effect 负责物理内存计量。一个 storage 上多个
语义不同的 alias 可能需要多个 `decision_value_ids`，不能仅凭 `storage_id` 猜测 AOT 边界。

诊断器生成的 `RepairHint` 会提高 residual boundary、alias base 或峰值 live storage 的候选
优先级，但不能绕过 legality pass。

## 8. 策略缺口与根因诊断

每个 baseline 和候选策略都必须生成：

```text
expected_saved_reduction
after_fw_retained_reduction
bw_recompute_transient_change
fixed_frontier_overlap
compiler/workspace/allocator_change
actual_overall_peak_reduction
```

因为峰值可能发生在不同 op/phase，上述量不能直接做无条件加法。系统使用反事实分层模型逐层
加入真实因素，定位预期收益在哪一层消失，并输出 `RootCause` 和 `RepairHint`。详细规范见
[08_min-cut缺口诊断与根因分析.md](08_min-cut缺口诊断与根因分析.md)。

## 9. Cost Provider

搜索只依赖统一接口：

```python
class CostProvider(Protocol):
    def supports(self, signature: OpSignature) -> bool: ...
    def estimate(self, signature: OpSignature) -> OpCost | None: ...
```

M0 不做 cost ranking。M1 使用 `Legacy Costmodel adapter -> FLOPs/static fallback`。M2 才启用
完整组合：

```text
exact ProfileDB
-> nearby-shape interpolation
-> Legacy Costmodel adapter
-> roofline/FLOPs fallback
```

Costmodel 不需要先整体重写。详细迁移方案见
[06_Costmodel与Profiling.md](06_Costmodel与Profiling.md)。

## 10. Peak-Aware 搜索

### 10.1 Min-cut seeds

使用 PyTorch min-cut 风格图和多组 Lagrangian 乘子生成不同保存比例的初解：

```text
score(x; lambda) = estimated_recompute_time(x)
                 + lambda * saved_memory_proxy(x)
```

min-cut 是 seed generator，不是最终预算判定器。

### 10.2 方案仿真

对每个 seed：

1. 推导未保存值的重计算闭包；
2. 生成或读取 partitioner 实际 backward 顺序；
3. 执行 storage liveness 仿真；
4. 记录 peak live set、峰值阶段和估计 step time；
5. 记录 `max_recompute_live_bytes`、`recompute_span_ops` 和
   `recompute_before_first_bw_op_bytes`。

三项重算波指标是一等约束：超过配置阈值的方案直接不可行；阈值未知或估计置信度不足时，作为
penalty 进入排序，并强制保留一个 wave-safe conservative plan 作为回退。

### 10.3 Peak-aware repair

超预算时，从峰值 live set 中寻找可释放 storage：

```text
repair_score(v) = bytes_released_at_peak(v)
                / incremental_recompute_us(v)
```

每次 move 后重新计算重计算闭包和峰值，避免把共享祖先成本重复相加。可采用：

- 提高峰值 storage 的 cut penalty；
- peak-set cover 约束；
- region/value DROP move；
- 重新求 min-cut。

优先应用诊断报告映射出的修复动作。例如 rematerialization wave 优先 SAVE residual boundary，
fixed frontier 则停止无效 DROP 搜索，cost misrank 则触发热点算子 profiling。

搜索引擎必须实现显式 early-stop policy。出现以下任一条件时，不再扩展更激进的 DROP move：

- `INFEASIBLE_BY_ACTIVATION_ONLY`；
- `LOW_ACTIVATION_HEADROOM` 且连续 move 的预测 peak gain 低于阈值；
- 峰值已由 fixed frontier 主导，DROP 只增加 step time；
- 重算波硬约束连续被触发，且不存在可保存的 residual boundary 修复。

early-stop 输出 reason、证据快照和 best-so-far plan；它不是仅供展示的 feasibility 状态。

### 10.4 可行解改进

满足预算后，尝试保存高重算代价值，只要新峰值仍不超过安全预算。支持单值 SAVE、region
SAVE 和 SAVE/DROP swap。

### 10.5 Pareto Top-K

先按 `(estimated_peak, estimated_step_time)` 建立 Pareto frontier，再用 `risk_score` 和
`confidence` 做 Top-K 分层排序。`risk_score` 汇总低置信度 cost、未知 workspace、compiler
materialization 残差、allocator 误差和重算波风险；同等 peak/time 下优先低风险、高置信度方案。
Top-K 同时保留少量高不确定性但潜在更优的探索方案，以及至少一个保守回退方案。

每个候选的排序记录固定包含：

```text
estimated_peak
estimated_step_time
risk_score       # 越低越好
confidence       # 越高越好
```

`risk_score` 和 `confidence` 必须有 `[0, 1]` 归一化定义、provenance 和稳定 tie-break，不能用缺失值
默认冒充零风险或高置信度。

## 11. 计划下发

```python
@dataclass(frozen=True)
class RecomputePlan:
    graph_key: str
    budget_bytes: int
    storage_effects: tuple[StorageEffect, ...]
    saved_value_ids: frozenset[int]
    mandatory_value_ids: frozenset[int]
    estimated_peak_bytes: int
    estimated_step_us: float
    max_recompute_live_bytes: int
    recompute_span_ops: int
    recompute_before_first_bw_op_bytes: int
    risk_score: float
    confidence: float
    safety_margin_bytes: int
    cost_sources: tuple[str, ...]
```

`storage_effects` 是计划内部的物理内存语义及评分依据；`saved_value_ids` 由通过 legality/closure
的 `decision_value_ids` lowering 得到，是 AOT partition ABI，不得反向用于重复计算 alias bytes。
对于通过 legality、closure 和结构检查的计划，自定义 AOT partitioner 根据 `saved_value_ids`
构造 FW outputs 和 BW placeholders。第一版支持纯函数、固定 shape、单设备、受控 RNG 且不存在
未建模 alias/mutation 的图；不支持梯度累积、FSDP/offload 和 dynamic shape。必须验证：

- FW output 与 BW input 一一对应；
- 参数、切线和 RNG 输入顺序正确；
- 未保存值只在合法位置重算；
- loss、输出和参数梯度与 baseline 在容差内一致。

## 12. Top-K 真实闭环

```text
static Pareto Top-K
-> AOT partition
-> aot_eager ABI/correctness dry-run
-> Inductor compile
-> warmup
-> compiled FW/BW + eager optimizer phase peak/time measurement
-> correctness check
-> fastest feasible plan
```

搜索预算使用安全裕量：

```text
search_budget = user_budget - max(fixed_margin, ratio_margin * user_budget)
```

若候选超预算，更新校准残差并加强 repair；若全部失败，回退到更保守的 checkpoint plan。

## 13. 可选吞吐增强（M3）

外层枚举 microbatch：

```text
for m in candidate_microbatches:
    obtain graph/guard-compatible IR
    search SAVE plans under B
select max(m / measured_step_time)
```

静态 shape 的 M3 实现允许每个 microbatch 具有独立 graph key。只有 dynamic/symbolic graph 经验证
稳定后，才宣称多个 microbatch 共用一次捕获。

## 14. 分期实现顺序

### M0：可运行闭环

1. optimizer/fixed frontier 粗分析；
2. 一次 joint capture、不可变 Value/Storage IR 和 legality；
3. all-save/min-cut/手工 SAVE plan 的 closure 与 baseline liveness；
4. 自定义 partition、aot_eager dry-run、梯度/RNG 正确性；
5. compiled FW/BW + eager optimizer 的完整 step peak/time。

### M1：PeakAware 搜索

1. Legacy Costmodel adapter 和静态 fallback；
2. storage-aware candidate、greedy/min-cut seeds 和 peak repair；
3. backward wave 约束、risk/confidence 和 early-stop；
4. Pareto Top-K 与少量 Inductor 实测。

### M2：研究工程化

ProfileDB、D0--D5、三层 cache、隔离 worker、插件替换点、主模型实验和报告。

### M3：扩展

dynamic shape、microbatch、MoE、exact solver 和分布式/offload 等独立研究方向。
