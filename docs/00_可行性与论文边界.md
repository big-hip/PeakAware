# PeakAware 可行性与论文边界

## 1. 结论

论文方向可行，但应定位为：

> 面向 PyTorch 编译训练端到端峰值显存约束的激活保存与重计算优化。

建议英文标题：

> PeakAware: End-to-End Peak-Constrained Activation Placement for Compiled PyTorch
> Training

论文不是泛化地研究“如何在有限内存下自动 checkpoint”，而是解决当前 PyTorch
saved-memory min-cut 与真实 FW/BW/optimizer 物理峰值之间的目标错位。

## 2. 已有工作覆盖了什么

以下方向已经有成熟工作，不能直接作为新的核心贡献：

| 工作 | 已覆盖内容 |
|---|---|
| [Checkmate](https://arxiv.org/abs/1910.02653) | 内存约束下的张量保存、删除、重计算调度与时间优化 |
| [Rotor](https://arxiv.org/abs/1911.13214) | 链式网络的最优 checkpoint 与重计算序列 |
| [MONeT](https://arxiv.org/abs/2010.14501) | checkpoint schedule 与算子实现联合优化 |
| [DTR](https://arxiv.org/abs/2006.09616) | 动态 tensor eviction/rematerialization |
| [POET](https://arxiv.org/abs/2207.07697) | 受限设备上的 rematerialization 与 paging 联合优化 |
| [Mimose](https://arxiv.org/abs/2209.02478) | 动态输入下的 checkpoint 规划与吞吐优化 |
| [Rockmate](https://arxiv.org/abs/2307.01236) | 从 PyTorch 模型自动生成 activation-budget plan |
| [Coop](https://arxiv.org/abs/2311.00591) | allocator fragmentation 与 rematerialization 联合优化 |
| [BladeDISC++](https://arxiv.org/abs/2412.16985) | 动态 shape 编译图中的 scheduling 与 rematerialization |
| [Hong et al.](https://arxiv.org/abs/2502.12499) | backward checkpoint subset 与训练峰值优化 |

因此以下表述不成立：

- 首次提出自动 SAVE/RECOMPUTE；
- 首次在内存预算下优化训练时间；
- 首次发现 checkpoint placement 会影响 backward peak；
- 一次捕获计算图本身构成主要创新。

## 3. 可形成贡献的缺口

PyTorch 官方说明 memory budget 指固定区域中为 backward 保存的内存，而不是完整 peak
memory。公开 residual issue 也表明 min-cut 可能保存 matmul 输出并重算长 add/residual 链。

本项目应把贡献收敛到：

1. 在当前 AOTAutograd/Inductor 栈中分解并验证 saved activation、rematerialization
   transient、gradient frontier、optimizer 和 workspace 对峰值的贡献。
2. 建立策略无关的期望收益差距诊断，解释 min-cut 或其他策略为何未兑现预计显存收益。
3. 基于一次 joint graph 构建包含 storage alias、phase liveness、fixed state 和 compiler
   correction 的校准后端到端峰值估计模型。
4. 保留 PyTorch min-cut 作为快速初解，用诊断结果和 peak live-set 反馈修复 SAVE 集合。
5. 通过插件化 Cost Provider 和 Top-K 真实编译校正，把计划下发为可执行 partition。
6. 在相同实测峰值下比较有效吞吐，而不是只比较 saved activation bytes。

公开依据：

- [PyTorch activation checkpointing 官方博客](https://pytorch.org/blog/activation-checkpointing-techniques/)
- [PyTorch issue #149258](https://github.com/pytorch/pytorch/issues/149258)
- [PyTorch partitioner source](https://github.com/pytorch/pytorch/blob/main/torch/_functorch/partitioners.py)

## 4. 正式研究问题

给定：

- 一次捕获的 AOTAutograd joint graph `G`；
- 候选前向值集合 `A`；
- 目标硬件 `H` 和编译配置 `C`；
- optimizer 配置 `O`；
- 用户物理峰值预算 `B`。

决策变量仅为：

```text
x_a = 1：值 a 跨越 FW/BW 边界 SAVE
x_a = 0：值 a 在 backward 需要时 RECOMPUTE
```

由 SAVE 集合 `x` 派生：

- partition 后的 FW/BW 图；
- 重计算闭包 `R(x)`；
- 当前 partitioner 产生的 backward 顺序 `pi(x)`；
- 编译器物化行为 `C(x)`。

主问题：

```text
minimize    T(x; H, C, O)
subject to  P(x, R(x), pi(x), C(x), O) <= B
            x satisfies legality constraints
```

第一版不搜索任意 `pi`。若未来加入 schedule 调整，也应作为插件或 Top-K 后处理，而不是阻塞
SAVE 优化主线。

## 5. “塞下模型”的准确边界

总显存至少包含：

```text
parameters
+ gradients
+ optimizer states
+ mandatory buffers
+ minimum runtime workspace
+ activations
```

若前五项已超过 `B`，系统应返回 `INFEASIBLE_BY_ACTIVATION_ONLY`。对于 LLaMA-7B/8B 全参数
AdamW 训练，固定状态通常已远超普通单卡容量；除非与 FSDP、ZeRO 或 offload 组合，否则
不能声称重计算可以单独“塞下”模型。

## 6. “充分利用算力”的准确口径

额外重计算会增加 hardware FLOPs，但不一定提高有效训练效率。论文主指标应是：

```text
fixed batch: minimize step_time under B
or
fixed task: maximize samples_per_second / tokens_per_second under B
```

解释性指标包括 MFU、HFU、SM Active、Tensor Core utilization 和 DRAM throughput。MFU 的
有效模型 FLOPs 不应把额外重计算 FLOPs 计为收益。

增强版本可以枚举 microbatch `m` 与 SAVE 方案 `x`：

```text
maximize    m / T(m, x)
subject to  P(m, x) <= B
```

该外层搜索用于证明释放显存可以转化为更大 microbatch 和更高吞吐，但不属于第一阶段必需
功能。

## 7. 模型范围

### 主实验

- ResNet-50：residual/CNN；
- ViT-B/16：attention/MLP/residual；
- BERT-Base：encoder；
- GPT-2：decoder 与 LM-head frontier。

GPT-2 XL 是否作为主实验取决于硬件。资源不足时使用小规格验证正确性，并明确全尺寸结果的
证据边界。

### 扩展实验

- Swin-T：window/shift 和图捕获稳定性；
- LLaMA-7B/8B：FakeTensor 全图分析，加缩小模型真实闭环；
- Mixtral-style Small MoE：固定 capacity 或可复现 routing trace 后再加入。

## 8. Go/No-Go 条件

在大规模实现前先完成机会验证：

1. 至少三个真实模型存在 activation 可优化空间，而非完全由固定 frontier 主导。
2. matched after-FW saved memory 下，min-cut 与 block AC 的 BW/overall peak 存在可解释差异。
3. Inductor 后现象仍存在，不能只依赖 AOT eager 合成图。
4. 一个简单 peak-aware greedy 已能在相同实测峰值下改善吞吐或预算满足率。

若只有合成 residual 图有明显问题，应把论文降级为诊断与峰值预测工具；若固定 frontier 在
大多数真实配置中主导，应把贡献重点改为可行性分析和无效重计算检测。

## 9. 最小可发表版本

以下是论文最小可发表版本，对应 M0--M2 的总和，不是首轮代码清单。M0 应先完成
capture -> IR -> hand plan -> partition -> full-step measurement，再进入自动搜索与工程化。

最小可发表版本包括：

- 一次 FakeTensor joint capture；
- Storage-Aware Joint IR；
- Fixed Frontier Analyzer；
- MinCut/Plan Root-Cause Analyzer；
- 任意 SAVE bitset 的重计算闭包和峰值仿真；
- min-cut seed + peak-aware repair；
- Costmodel/ProfileDB 可插拔 cost；
- 自定义 AOT partition 下发；
- Top-K 实测校正和计划缓存；
- 四类模型上的预算、吞吐和消融实验。

CPU/NVMe offload、activation compression、任意 schedule 搜索和分布式联合优化均为后续扩展。
