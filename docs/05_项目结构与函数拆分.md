# PeakAware 项目结构与函数拆分

## 1. 实现阶段与最小代码树

文档中的最终能力不等于首版文件清单。实现按四期推进，后一期只能依赖前一期稳定契约：

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| M0 可运行闭环 | 一次捕获、storage IR、手工计划、partition、正确性和真实峰值 | Tiny residual 的至少三种计划可执行 |
| M1 PeakAware | min-cut/greedy seed、peak repair、wave/risk、Top-K | 相同预算下优于或稳定匹配 min-cut |
| M2 研究工程化 | ProfileDB、D0--D5、三层 cache、插件替换点 | 多模型实验可复现且可解释 |
| M3 扩展 | dynamic shape、microbatch、MoE、exact solver、论文报告 | 不修改 M0/M1 核心数据契约即可接入 |

树中省略各 package 的空 `__init__.py`；它们只声明包边界，不放置注册或副作用逻辑。

现有 `Costmodel/` 和 `Optim_IR/` 保留为参考/适配来源，不直接成为新包内部依赖边界。
`ActivationPlanner` 只负责 activation storage 的 SAVE/DROP；optimizer 仅由 `StepPeakModel` 和
`FixedMemoryProvider` 纳入 phase peak，MVP 不依赖 `Optim_IR/` 才能运行。

M1 再加入 `cost/{base,legacy_adapter}.py`、拆出
`search/{candidates,seeds,greedy,repair,pareto}.py` 和基础 `diagnostics.py`；M2 再加入 `plugins/`、
`cache/`、ProfileDB、完整 `diagnostics/`、runtime isolation 和 reporting；M3 才加入 `exact.py`、
模型注册、dynamic/microbatch/MoE。禁止为了未来文件名提前创建只有占位符的模块。

M0 支持域固定为：单设备、静态 shape、纯函数或已函数化图、受控 RNG、单 batch 单 optimizer
step、无梯度累积、无 FSDP/offload。M0 默认关闭 autocast/GradScaler；AMP 在 M1 正确性稳定后加入。
超出支持域必须 fail closed 或返回明确的 unsupported reason，不能静默进入未验证路径。

## 2. 顶层 API

```python
def optimize_training(
    model: nn.Module,
    example_args: tuple,
    *,
    example_kwargs: dict | None = None,
    loss_fn: Callable,
    optimizer: torch.optim.Optimizer,
    memory_budget_bytes: int,
    config: PeakAwareConfig | None = None,
) -> OptimizedTrainingResult:
    ...
```

编排顺序：

```text
validate_request
-> analyze_fixed_frontier
-> capture_joint_graph
-> build_joint_ir
-> build_baselines
-> M0: evaluate_configured_plans
   M1+: build_cost_provider -> search_plans
-> lower_and_dry_run_candidates
-> compile_and_measure_candidates
-> choose_plan
-> build_training_step_executor
```

`api.py` 不实现算法细节。M0 不要求通用 plugin registry；M2 引入插件后，在
`validate_request` 前增加 `build_registry`，但不得改变其余阶段输入输出。

### 2.1 Optimizer 与运行期边界

M0/M1 只捕获和编译 AOTAutograd FW/BW joint graph，optimizer 不进入 SAVE 搜索，也不进入该
joint graph。`optimizer` 实例用于：

1. 派生不可变 `OptimizerSpec` 和 fixed-memory estimate；
2. 在隔离验证副本上执行 eager `optimizer.step()`，测量 optimizer phase peak/time；
3. 由最终 `TrainingStepExecutor` 在 compiled FW/BW 后调用原 optimizer。

```python
class TrainingStepExecutor(Protocol):
    def step(self, *args, **kwargs) -> StepResult:
        """zero_grad policy -> compiled FW/BW -> eager optimizer.step."""
```

候选验证必须克隆 model state、optimizer state 和 RNG，不得推进用户原始训练状态。fallback 只替换
compiled FW/BW executable，不重建或丢弃用户 optimizer state。

### 2.2 阶段产物契约

所有跨阶段流水线产物集中定义在 `contracts.py`，包括 `JointTrainingIR`、`SimulationResult` 和
`RecomputePlan`；CostProvider 等基础协议由其基础模块拥有。各模块内部的临时 builder/event/move
类型留在所属模块，禁止再次定义同名公共类型。至少固定以下流水线：

```text
TrainingRequest
-> CapturedJointGraph
-> JointTrainingIR + IRValidationReport
-> AnalysisBundle
-> RecomputePlan
-> EvaluatedPlan
-> LoweredPartition
-> DryRunResult
-> MeasuredExecutable
-> OptimizedTrainingResult
```

最低字段要求：

```python
from __future__ import annotations

@dataclass(frozen=True)
class CapturedJointGraph:
    joint_module: GraphModule
    guards: tuple[GuardSpec, ...]
    parameter_mapping: tuple[ParameterBinding, ...]
    capture_key: str

@dataclass(frozen=True)
class IRValidationReport:
    valid: bool
    errors: tuple[str, ...]
    warnings: tuple[str, ...]

@dataclass(frozen=True)
class AnalysisBundle:
    ir: JointTrainingIR
    fixed_timeline: FixedTimeline
    baseline_results: tuple[EvaluatedPlan, ...]
    analysis_key: str

@dataclass(frozen=True)
class EvaluatedPlan:
    plan: RecomputePlan
    simulation: SimulationResult
    feasible: bool
    rejection_reason: str | None

@dataclass(frozen=True)
class LoweredPartition:
    plan_id: str
    fw_graph: GraphModule
    bw_graph: GraphModule
    partition_abi: PartitionABI

@dataclass(frozen=True)
class PartitionABI:
    fw_output_value_ids: tuple[int, ...]
    bw_placeholder_value_ids: tuple[int, ...]
    tangent_value_ids: tuple[int, ...]
    rng_state_value_ids: tuple[int, ...]

@dataclass(frozen=True)
class MeasuredExecutable:
    plan_id: str
    forward_backward: Callable
    measured_peak_bytes: int
    measured_step_us: float
    correctness_passed: bool

@dataclass(frozen=True)
class DryRunResult:
    plan_id: str
    abi_valid: bool
    outputs_match: bool
    gradients_match: bool
    rng_match: bool
    failure_reason: str | None

@dataclass(frozen=True)
class OptimizedTrainingResult:
    selected_plan: RecomputePlan
    executable: MeasuredExecutable
    executor: TrainingStepExecutor
    feasibility: FeasibilityReport
    fallback_plan_ids: tuple[str, ...]

@dataclass(frozen=True)
class StepResult:
    loss: Tensor
    optimizer_step_performed: bool
```

每个阶段只消费前一阶段公开对象，不读取其他模块私有缓存或可变全局状态。

| 产物 | 生产者 | 必须满足的不变量 |
|---|---|---|
| `CapturedJointGraph` | capture | pre-partition、guards/parameter mapping 完整、同 request 只捕获一次 |
| `JointTrainingIR` | ir | stable ids、alias/storage 不重复、不可变 |
| `AnalysisBundle` | memory + baseline builder | fixed timeline 与 baseline 使用同一 graph key |
| `RecomputePlan` | search | legality/closure 已通过，value 语义与 storage effect 同时保留 |
| `EvaluatedPlan` | memory simulator | 不修改 plan；不可行必须有 rejection reason |
| `LoweredPartition` | partition | FW/BW ABI 与 plan id 一致 |
| `DryRunResult` | partition verifier | ABI、梯度和 RNG 分项报告，不用单一 bool 隐藏原因 |
| `MeasuredExecutable` | runtime | 只有 correctness 通过的 executable 才能参与最终选择 |
| `OptimizedTrainingResult` | api | executor、plan、measurement 和 fallback provenance 一致 |

### 2.3 依赖 DAG

下图中 `A -> B` 明确表示“A 可以 import B”，不是运行时数据流：

```text
api -> capture / ir / memory / cost / search / partition / runtime

search    -> memory / ir / cost / contracts
partition -> ir / contracts
memory    -> ir / contracts
capture   -> contracts / config
ir        -> contracts
cost      -> contracts
runtime   -> contracts / config
diagnostics -> contracts

plugins/cache (M2) -> 上述公开 protocol/contract
核心模块 -X-> plugins/cache
```

- `contracts.py` 不导入任何业务模块，只依赖标准库、公开 PyTorch 类型和 forward annotation；
- `ir` 不导入 `capture/memory/search/partition/runtime`；
- `memory` 不导入 `capture/search/partition/runtime`；
- `search` 只消费 IR、memory result 和 CostProvider，不导入 PyTorch 私有 API；
- `partition/runtime` 不反向修改 plan 或 IR；
- diagnostics 生成报告或 hint，不直接执行 search move；
- cache 和 plugin 在 M2 作为外围 adapter，不成为核心算法必经中间层。

### 2.4 职责所有权

容易重叠的能力必须只有一个写入所有者：

| 能力 | 唯一所有者 | 其他模块允许做什么 |
|---|---|---|
| value/storage/alias/legality | `ir/` | memory/search 只读 |
| alloc/free/recompute timeline 与 `PeakSnapshot` | `memory/`，公共类型在 `contracts.py` | diagnostics 比较，search 消费 |
| region 结构标注 | `ir/regions.py`（M1） | search 将标注转成 candidate |
| candidate、move、repair | `search/` | diagnostics 只返回 hint，不执行 move |
| partition ABI 与 value-node mapping | `partition/` | runtime 只执行已验证产物 |
| correctness 与 aot_eager dry-run | `partition/verifier.py`（M0） | M2 可拆文件但不复制规则 |
| 峰值文字解释与根因报告 | `diagnostics/` | memory 只返回结构化 snapshot |
| optimizer state 生命周期 | 用户 optimizer + `runtime/executor.py` | search 不读取或修改 optimizer state |
| cache key 与序列化 | `cache/`（M2） | 核心模块不主动访问 cache |

## 14. 模型注册（M3）

```python
@dataclass(frozen=True)
class TrainingTaskSpec:
    name: str
```

## 15. 测试布局

### Unit

M0：alias/storage、closure、fixed frontier、liveness、partition ABI、gradient/RNG correctness。

M1：storage effect、alias pinning、early-stop、recompute-wave metrics、risk ranking、repair、Pareto。

M2：counterfactual ladder、root-cause rules、ProfileDB、三层 cache key/级联失效、plugin registry、
patch restore。

### Integration

M0 固定一条 Tiny residual 的 capture -> IR -> hand plan -> partition -> aot_eager dry-run -> eager
optimizer step。M1 再加入 Tiny MLP/attention 和自动搜索。

### Correctness

M0：loss、gradients、受控 RNG、shared storage。

M1：AMP/GradScaler、tied weights 和更多 optimizer；M3：dynamic shape、gradient accumulation、
microbatch 和分布式语义。

### Compatibility（M2）

主支持 PyTorch 版本的私有 API 签名、patch target 和 graph metadata。

### Performance（M1 起）

峰值误差、cost ranking、搜索耗时、编译 Top-K、吞吐和 amortization steps。

## 16. 依赖规则

- `ir/`、`memory/`、`search/` 不导入 PyTorch 私有模块；
- M0 私有 API 只出现在 `capture` 和 `partition` 的 adapter；M2 可迁移到 `plugins/builtin`；
- `Costmodel/` 只通过 `LegacyCostmodelAdapter` 访问；
- `Optim_IR/` 只允许通过可选 adapter/provider 访问，`ActivationPlanner` 不导入它；
- diagnostics/reporting 不参与算法决策，只能生成结构化 hint；
- 插件不能跨层直接修改全局状态；
- M2 runtime worker 使用序列化 plan/配置，不共享 patched interpreter 状态。

## 17. 扩展准入规则

新增目录、插件点或抽象必须同时满足：

1. 已有至少两个真实实现或一个明确的版本隔离需求；
2. 输入输出使用 `contracts.py` 或所属模块公开不可变类型；
3. 不引入逆向 import，不允许通过全局状态绕过依赖 DAG；
4. 有独立单测，并有一条端到端测试证明替换前后语义一致；
5. 能说明属于 M1/M2/M3 哪个 gate，不能以“以后可能用到”作为创建理由。

文件拆分以职责和替换边界为准，不以函数数量为准。尚未满足准入条件的能力先作为现有模块内的
私有函数实现，等契约稳定后再提取。
