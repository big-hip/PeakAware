# 论点与故事线

## 1. 用 Heilmeier 八问约束故事

| 问题 | PeakAware 的回答 |
|---|---|
| 要做什么 | 在用户给定的完整训练物理峰值预算下选择 activation SAVE 集合，并提高有效吞吐 |
| 今天怎么做 | 手工 AC、SAC、AOTAutograd min-cut 或 saved-memory budget |
| 当前限制 | saved activation 不是完整 peak，alias、BW transient、gradient、optimizer、workspace 会改写收益 |
| 新方法是什么 | D0--D5 差距诊断、storage/phase-aware peak model、diagnosis-driven repair、Top-K 实测闭环 |
| 为什么会成功 | 决策和验收使用同一个 physical-peak 目标，且计划下发为实际 FW/BW executable |
| 谁关心 | 在单卡预算下训练编译模型、调 AC/min-cut 策略、排查峰值反升的开发者和研究者 |
| 风险是什么 | 真实 min-cut baseline、compiler variance、fixed frontier、模型规模和内部 API 稳定性 |
| 如何验收 | RQ-1--RQ-5、G-1--G-9 和 evidence ledger |

## 2. 五幕故事

### 第一幕：一个看似正确但不完整的目标

Activation checkpointing 和 min-cut 通过减少为 backward 保存的 tensor 换取重计算。该目标有用，
但 saved-memory budget 不等于完整训练 step 的物理峰值预算。

### 第二幕：收益为什么消失

逻辑 tensor 可能共享 storage；减少 after-FW retained memory 后，backward 可能形成重计算波；峰值也
可能迁移到 gradient 或 optimizer frontier；compiler workspace 进一步改变真实峰值。因此“少保存”
不蕴含“overall peak 同比例下降”。

### 第三幕：先解释，再优化

PeakAware 用统一 storage 模型计算 strategy expectation gap、normalized saved gain、realization gap，
并通过 D0--D5 反事实确定收益消失在哪一层。诊断输出必须包含证据、置信度和可执行 repair hint。

### 第四幕：让搜索目标与验收目标一致

系统以 min-cut/block/greedy 为 seeds，消费 peak live set 和诊断 hints 修复 SAVE 集合，再通过
Pareto Top-K 控制编译成本。搜索内部使用模拟峰值，最终只接受正确性通过且实测物理峰值满足预算
的 executable。

### 第五幕：可执行闭环和诚实边界

计划下发为 AOT FW/BW GraphModule，optimizer 作为 eager phase 进入完整 step。结果同时报告 raw
预测、all-save 校准、失败候选、固定 frontier 和负收益点；论文不把 calibration 写成纯静态精度。

## 3. 核心论点卡

### C-1 目标错位可观测且可分解

- 一句话：saved activation 的下降与 complete-step physical peak 的下降之间存在可测量差距。
- 机制：storage alias、recompute transient、fixed frontier、phase migration、workspace。
- 证据需求：真实 PyTorch baseline、逐 phase measurement、至少三个架构。
- 反例责任：若某模型 saved gain 与 peak gain 一致，应报告为该 workload 不受错位影响。
- 禁止外推：不能声称所有 min-cut 或所有 checkpoint 都会造成峰值反升。

### C-2 D0--D5 能解释收益缺口

- 一句话：逐层加入 storage、liveness、fixed state 和 runtime correction，可定位主要误差来源。
- 证据需求：合成 ground truth precision/recall，真实模型 cause frequency 和 waterfall。
- 边界：真实模型没有完备人工真值；D4/D5 依赖 compiler/runtime measurement。

### C-3 PeakAware 能生成真实可执行计划

- 一句话：SAVE 集合不是报告标签，而是被 lower 为经数值验证的 FW/BW executable。
- 证据需求：plan identity、lowered replay、复杂 pytree、isolated worker、multi-step correctness。
- 边界：静态 shape、单设备、当前 PyTorch 私有 AOT ABI。

### C-4 Peak-aware 选择在目标预算下改善 Pareto 结果

- 一句话：在相同或更低实测 peak 下，PeakAware 相对关键 baseline 提高有效吞吐或保持不劣。
- 证据需求：真实 baseline、紧预算、四模型、Pareto 图、逐点胜负而非只报均值。
- 边界：不得声称全面支配 SAC；必须报告严格 peak win 比例。

### C-5 优化成本可被 Top-K 和 cache 控制

- 一句话：只编译少量多样候选，并复用分析和 measurement，可摊销优化成本。
- 证据需求：分阶段优化时间、cache cold/warm、amortization steps、ranking ablation。
- 边界：当前 cost ranking 偏弱，应把 Top-K 校正写成必要机制而非附加优化。

## 4. 创新点写法

创新点必须采用“缺口 -> 机制 -> 与已有工作的差异 -> 证据”的句式：

1. 针对 saved-memory 与 complete-step physical peak 的目标错位，提出策略无关的收益差距分解和
   D0--D5 反事实诊断，而不是再次提出通用 rematerialization。
2. 针对 logical tensor bytes 无法代表真实峰值的问题，建立 storage alias、phase transient、fixed
   frontier 和 compiler correction 组合的峰值模型。
3. 针对 min-cut seed 可能落在错误峰值边界的问题，以 root-cause evidence 和 peak live set 驱动
   SAVE repair，并用 Top-K 实测纠正静态排序。
4. 构建从一次 joint capture、计划身份、AOT partition、正确性验证到完整训练 step 的可执行闭环。

插件、cache、ProfileDB 是支撑 C-3/C-5 的工程机制，不单独包装成核心理论创新。

## 5. 摘要五句模板

1. 背景：编译训练使用 activation rematerialization 缓解显存压力。
2. 缺口：现有 saved-memory 目标没有直接约束由 FW/BW/optimizer 共同决定的物理峰值。
3. 方法：本文提出 PeakAware，包含何种峰值模型、诊断和 SAVE repair。
4. 实现：说明 joint graph、AOT partition、Top-K measurement 和 eager optimizer 闭环。
5. 结果：仅在 G-7 后填入四模型、真实 baseline、预算、峰值、吞吐、误差和开销数字。

摘要不放 synthetic F1 作为第一结果；核心结果优先是物理峰值预算和吞吐。

## 6. 引言漏斗

1. 训练显存限制 batch、sequence 和模型规模；activation 是可优化但非唯一组成。
2. 说明 AC/min-cut 的 memory-compute tradeoff 及其 saved-memory 语义。
3. 用一个真实动机图展示 expected saved gain 与 overall peak gain 不一致。
4. 提出三个挑战：物理 storage、跨 phase frontier、compiler/runtime gap。
5. 概述 PeakAware 的“解释 -> 修复 -> 下发 -> 实测选择”闭环。
6. 列出四项贡献，每项指向一个 `C-*` 和一个结果图。

## 7. 负结果如何进入故事

- 当前 runtime 重跑后若严格 peak win 比例较低：检验是否由 fixed/optimizer frontier 主导，并把
  逐点胜负而非旧矩阵数字写入正文；
- 真实 hints neutral：说明诊断有解释价值，但并非每个搜索面都能被 hints 改变；
- cost ranking 弱：说明 Top-K runtime correction 必须存在；
- SAC 显存更低但更慢：用 Pareto 权衡代替“全面胜出”；
- raw error 高、calibrated error 低：明确静态模型与 baseline-assisted online model 的边界。

## 8. 禁止表述

- 首次提出 activation checkpointing、automatic rematerialization 或 memory-time tradeoff；
- 完整复现 PyTorch min-cut（在 G-1 通过前）；
- BERT-Base/GPT-2 标准模型（在 G-2 通过前）；
- 四模型 Inductor 主矩阵已完成（在 G-4 通过前）；
- 所有配置都降低峰值；
- 纯静态模型达到校准后的误差；
- 根因系统在真实模型上达到 100% 准确率；
- PeakAware 全面支配 SAC 或所有 AC 方法。
